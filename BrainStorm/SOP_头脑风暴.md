# SOP：日常头脑风暴、复盘与思考沉淀

## 0. 定位

BrainStorm 的默认任务是帮助用户持续思考和复盘，不是每次寻找内核改动。先把原始现场与上下文保存好；只有用户明确提出，或材料暴露稳定规则冲突时，才进入“内核演化判断”。

## 1. 加载

读取：

1. `MEMORY.md`；
2. `状态机/STATUS.md`；
3. 近期 `Summarized_Insights/`；
4. 话题涉及“最近在看什么”时，可选读取 `../持仓与关注/当前关注方向与投资偏好.md`；
5. 涉及具体策略或动作决策时，才读取当前 Strategy Profile 和对应决策状态；
6. 只有话题涉及过去经历、投资诊断或内核入职时，才先读 `历史投资资料/资料索引.md` 与相关梳理，再按索引打开代表原文。

日常对话不全量加载历史投资资料，也不默认读取所有 Raw。上下文过多时，优先保留长期背景、当前状态、近期变化和与当前问题直接相关的原文。

## 2. 原始记录

Raw Thought 至少保留：时间、原始观点、当时信息、触发事件、情绪/动机、反例和待验证条件。原始记录不为了“更正确”而改写。

## 3. 结构化总结

```markdown

## 关键洞察
- 事实：
- 解释：
- 假设：

## 反例与未知
-

## 下一步验证
- [ ]

## YMOS 联动

- 证据应写入：

## 内核演化判断
- 暂不处理 / 继续积累 / 起草变更提案

```

## 4. 升级判据

“是否升级”是可选审查，不是每次头脑风暴的必填结果。多数 Insight 正常停留在“继续观察”或“无需联动”。

从 Insight 升级为内核候选，不使用公共固定次数。至少检查：

- 是否跨多个独立案例，而非同一事件的重复描述；
- 是否有反例和适用边界；
- 问题属于策略结果、执行偏差、内核冲突还是投研数据质量；
- 改动是否能写出预期效果、证伪条件、观察期和回滚方案；
- 证据强度是否达到当前 Profile 由 Human 定义的门槛。

满足后只起草 `Brain/内核审计/_模板_判断层变更提案.md`，不得直接改 Profile。若依据主要来自 BrainStorm / 旧日志，提案必须标记为**规则澄清型**和 `trial`，不得声称交易结果已验证；若声称规则更有效，则转入周期审计等待跨笔证据。

## 5. Human 确认点

- 追加长期 MEMORY 前确认；
- 将洞察升级为框架或清单前确认；
- 新建内核变更提案前确认范围；
- 把头脑风暴中的临时兴趣或当前主题写入轻量关注文件前，单独展示草案并调用 `../持仓与关注/SOP_关注方向维护.md`；
- 合并变更到 Strategy Profile 前明确批准；
- 到达复审日后决定保留、修订或回滚。

## 6. 历史资料联动

- 新增旧日志时，转入 `SOP_历史投资资料入职.md`，不在本 SOP 中临时做全仓总结。
- 投资诊断先读索引和阶段梳理，再选择代表原文；不得只挑支持用户当前说法的材料。
- 旧日志中的规则必须标注“当时观点 / 事后解释 / 当前是否认可”，不能直接写入 MEMORY 或 Profile。
- 历史资料适合帮助用户看清策略来路和矛盾；若要证明规则更有效，仍需正式买卖决策与平仓结果证据。

## 纪律

- 不用结果盈亏替代过程审计。
- 不把 Agent 建议写成已生效规则。
- 不把一次头脑风暴自动写成当前关注，也不把当前关注当成 Profile。
- 不覆盖历史版本和当时信息集。
- 不把示例参数复制到用户 Profile。
