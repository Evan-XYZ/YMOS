# SOP：历史投资资料入职与思维梳理

> 暗号：`整理我的历史投资资料` / `用这些旧日志帮我做投资诊断`

## 定位

把用户已有的投资日志、复盘、感悟和旧策略文件变成**可检索的个人思考地图**。本流程不改原文、不自动训练策略，也不把旧观点直接写入当前 Strategy Profile。

## Step 0：确认授权与边界

1. 只处理用户主动放入 `BrainStorm/历史投资资料/原始资料/` 或明确指定的文件。
2. 默认不联网、不上传、不移动原件；需要转换格式时在同目录或临时目录生成 Markdown 副本。
3. 不在对话或日志中回显私人账户、Key、身份证明等敏感内容。
4. 用户未授权时，不递归扫描整个 Obsidian Vault、个人目录或聊天历史。

## Step 1：盘点，不先总结

先建立文件清单，记录：

- 相对路径、原文件名、日期或时期；
- 文件类型与是否可直接读取；
- 市场、标的、策略主题、材料类型；
- 是否包含真实交易、账户、私人信息；
- 是否可能与其他文件重复或属于同一系列；
- 当前读取状态：未读 / 已索引 / 已抽样 / 已深读。

将结果写入由 `_模板_资料索引.md` 复制出的 `资料索引.md`。无法识别日期时保留“未知”，不要从文件修改时间冒充内容发生时间。

## Step 2：按阶段与主题建立地图

优先按以下维度分组，不强迫所有资料使用同一种分类：

1. 时间阶段或市场环境；
2. 市场与策略结构；
3. 材料类型：交易日志 / 周月复盘 / 个股研究 / 原则感悟 / 旧规则；
4. 主题：入场、认错、仓位、期限、选股、退出、情绪、执行；
5. 观点状态：当时认可 / 后来修订 / 已放弃 / 当前未知。

先形成“我有哪些材料”的地图，再决定深读哪些。文件较多时，不允许一开始把全部全文塞进同一个上下文。

## Step 3：代表性抽样

抽样要覆盖差异，而不是只选印象最深或盈利最多的记录：

- 不同市场阶段；
- 成功与失败；
- 判断正确但执行错误、判断错误但碰巧盈利；
- 用户后来改口或反复摇摆的主题；
- 与当前自我描述一致和不一致的样本。

所有提炼都保留来源文件和原文位置。无法确认是当时观点还是事后总结时，明确标记。

## Step 4：生成阶段梳理

使用 `历史投资资料/索引与梳理/_模板_历史资料梳理.md`，至少输出：

- 材料覆盖范围与明显缺口；
- 用户长期不变的关注点；
- 随时期变化的策略与裁判；
- 反复出现的行为模式；
- 自我描述与实际记录的矛盾；
- 已放弃、仍认可、当前不确定的原则；
- 需要 Human 进一步回答的问题；
- 下一次诊断或策略梳理值得读取的代表原文。

这份梳理是导航，不是对用户的最终定性。

## Step 5：按任务调用

### 日常头脑风暴

默认只读 `MEMORY.md`、`STATUS.md` 和近期 Insight。只有当前话题与历史索引中的主题相关时，才打开一至数份代表原文。

### 投资诊断 / 内核入职

读取顺序：

```text
资料索引
  → 最近一次阶段梳理
  → 与诊断问题有关的代表原文
  → 用户当前口述
  → 结构诊断
```

发现矛盾时问 Human：“这条旧规则现在还认可吗？”不得以旧日志覆盖用户当前明确选择，也不得把用户今天的自我描述当成历史事实。

### 内核优化

历史资料可以支持**规则澄清型**提案：证明规则表达长期矛盾或真相源不一致。若要声称某条规则更有效，仍需买卖决策事件流、平仓复盘和跨笔结果证据。

## 完成标准

- 原始资料未被改写或移动；
- `资料索引.md` 能回答“有什么、在哪、处于什么阶段”；
- 至少一份阶段梳理列出来源、反例、缺口和待 Human 澄清问题；
- 观点状态与证据类型没有混淆；
- 没有自动修改 MEMORY、Profile、P、SOP 或 Console 规则；
- 用户知道下次如何继续追加新资料。
