# BrainStorm — 个人投资思考与复盘工作区

> 先长期保存“我怎么想、为什么这样想、后来怎么看”，再按需要把其中一小部分用于投资诊断、策略梳理或内核优化。

BrainStorm 是 YMOS 中可以长期使用的个人工作区，不只是内核审计的临时材料库。它的日常价值是帮助用户形成稳定习惯：保留原始思考、整理阶段 Insight、复盘自己的判断与行为、让下一次对话接得上前一次。

```text
已有投资日志 ──→ 建索引与阶段梳理 ───────────────┐
                                                    ├→ 带上下文的诊断 / 复盘 / 日常思考
当天 Raw Thought → Insight → MEMORY / 候选框架 ──┘
                                                    ↓ 只有明确需要时
                                           内核变更提案 → Human 审批
```

**不是每次头脑风暴都要改策略。** 很多记录的价值只是让你更理解自己、避免遗忘或事后合理化。只有当材料暴露出稳定规则的歧义、冲突，或真实结果提供了足够证据时，才进入内核变更流程。

## 1. 一句话理解每类文件

| 文件或目录 | 回答什么 | 日常是否读取 |
|:---|:---|:---|
| `MEMORY.md` | 哪些长期背景与认知值得反复想起？ | 每次头脑风暴读取 |
| `状态机/STATUS.md` | 我现在处于什么阶段、最近在纠结什么？ | 每次头脑风暴读取 |
| `Summarized_Insights/` | 最近新增了哪些观点、问题与行动项？ | 读取近期少量文件 |
| `每日头脑风暴/Raw_Thoughts/` | 当时原话、上下文和心理状态是什么？ | 写入为主，复盘时按需读取 |
| `历史投资资料/` | 用户过去已经积累了哪些日志、复盘和感悟？ | 先读索引，相关任务才读原文 |
| `投资感悟归档/` | 哪些想法值得长期观察或转成行动清单？ | 按主题读取 |
| Strategy Profile | 我现在正式按什么规则判断？ | 进入策略任务时读取 |

一句话：**MEMORY 保存长期背景，STATUS 保存当前位置，Insight 保存近期变化，Raw 保存原始现场，历史资料保存策略的来路，Profile 保存当前生效规则。**

## 2. 目录结构

```text
BrainStorm/
├── README.md
├── MEMORY.md
├── SOP_头脑风暴.md
├── SOP_历史投资资料入职.md
├── 状态机/
│   └── STATUS.md
├── 每日头脑风暴/
│   └── Raw_Thoughts/YYYY-MM/YYYY-MM-DD.md
├── Summarized_Insights/
│   └── YYYY-MM/YYYY-MM-DD_Insight.md
├── 历史投资资料/
│   ├── README.md
│   ├── 原始资料/                  # 用户旧日志原件；Git 默认忽略
│   ├── 资料索引.md                # 由模板复制后生成；Git 默认忽略
│   └── 索引与梳理/               # 阶段总结、矛盾地图、代表样本
├── 投资感悟归档/
│   ├── 短期灵感/
│   ├── 长期框架/
│   └── 执行清单/
└── scripts/brainstorm_memory.py
```

公开仓库只提供骨架和模板。用户的历史日志、Raw、Insight、资料索引和梳理报告默认被 Git 忽略，避免把私人思考误提交到公开仓库。

## 3. 三条日常工作流

### 3.1 日常思考：先说，再整理

```text
开始今天的头脑风暴
  → 读 MEMORY + STATUS + 近期 Insight
  → 围绕今天真正困扰的问题对话
  → 原样保存 Raw Thought

整理一下今天说的
  → 区分事实 / 解释 / 假设 / 情绪
  → 形成 Insight、待验证问题和行动项
  → 由 Human 决定是否更新 MEMORY 或 STATUS
```

原始记录不要为了“显得正确”而改写。Insight 可以更清楚，但必须保留对 Raw 的引用。

### 3.2 复盘习惯：记录判断，也记录自己

BrainStorm 不替代正式的交易事件流。它补的是结构化交易记录很难保存的部分：

- 为什么当时特别想买、特别不想卖；
- 哪条信息让你改变了注意力；
- 你是在执行原规则，还是在临场给动作找理由；
- 事后看，判断问题和执行问题分别是什么；
- 哪个问题仍没有答案，应该在下一次继续追。

一笔正式交易的成交、成本和生命周期仍以 `Brain/买入卖出决策/` 为事实源；BrainStorm 保存的是它背后的思考现场。

### 3.3 已有资料入职：先建地图，不做“大总结”

如果用户已经有多年的投资日志、Obsidian 笔记、复盘文档或投资感悟：

1. 把副本放进 `历史投资资料/原始资料/`，保留原件和原始日期。
2. 说“整理我的历史投资资料”，按 `SOP_历史投资资料入职.md` 建立 `资料索引.md`。
3. Agent 先按时期、市场、策略主题和材料类型做地图，不急着下结论。
4. 再抽取有代表性的阶段、成功与失败、规则变化和矛盾，写入 `索引与梳理/`。
5. 做投资诊断或配置内核时，先读索引和相关梳理；只有需要核对原话时才打开对应原文。

旧日志是**回忆与认知证据**，可能包含事后解释、当时的信息缺口和已经放弃的观点。Agent 必须区分“当时明确写下的规则”“后来总结的解释”和“现在仍被用户认可的规则”。

## 4. 它怎样帮助投资诊断与内核入职

历史资料和 BrainStorm 能帮助回答：

- 用户实际反复使用的入场依据是什么，而不只是今天自称什么流派；
- 哪些认错规则只写过但没有执行；
- 仓位、期限和论点是否长期互相冲突；
- 哪些行为弱点在不同市场和阶段重复出现；
- 哪些原则已经被用户明确放弃，却可能又悄悄回来。

正确顺序是：

```text
资料索引与代表原文
  → 结构诊断提出问题
  → Human 澄清“现在还认不认可”
  → Strategy Profile 草案
  → Human 逐段确认
```

Agent 不能从旧日志直接生成生效 Profile，也不能用历史材料替用户填写仓位、止损、期限等当前参数。

## 5. 内核优化只是反馈回路，不是日常 KPI

BrainStorm 中的材料有三种常见去向：

| 材料 | 最常见去向 | 是否改变内核 |
|:---|:---|:---:|
| 一次想法、困惑、情绪 | Raw / Insight，等待继续观察 | 否 |
| 长期仍认可的背景或认知 | Human 确认后更新 MEMORY | 否 |
| 可重复使用的思考方法或提醒 | 长期框架 / 执行清单候选 | 不自动改变 |
| 明确暴露规则歧义或冲突 | 规则澄清型提案，先 trial | 需 Human 审批 |
| 声称某条规则更有效 | 等待跨笔操盘证据与周期审计 | 需结果验证 |

BrainStorm 可以推动规则澄清型提案，但不能因为一条感悟反复出现就声称它有效。真正进入稳定内核仍需写明反证、观察期和回滚条件，并由 Human 批准。

## 6. 常用口令

| 口令 | 作用 |
|:---|:---|
| `开始今天的头脑风暴` | 加载长期记忆、当前状态和近期 Insight，继续今天的思考 |
| `整理一下今天说的` | 保存 Raw，形成 Insight 草稿与待验证问题 |
| `把这个感悟沉淀下来` | 由 Human 选择进入 MEMORY、短期灵感或长期框架候选 |
| `整理我的历史投资资料` | 盘点旧日志并建立索引，不修改原文 |
| `用这些旧日志帮我做投资诊断` | 先读索引与相关原文，再进入结构诊断 |
| `给我下一步行动指南` | 从 STATUS 与近期 Insight 生成待确认清单 |
| `检查是否值得改内核` | 仅在用户明确要求时审查证据、反例与缺口 |

## 7. 脚本使用

```bash
# 日常预览：MEMORY + 最近 7 天 Insight
python3 BrainStorm/scripts/brainstorm_memory.py --preview

# 内核入职或历史复盘：额外加载历史资料索引与最近梳理
python3 BrainStorm/scripts/brainstorm_memory.py --preview --include-history

# 扩大近期 Insight 窗口
python3 BrainStorm/scripts/brainstorm_memory.py --preview --days 14
```

脚本只负责加载和整理本地上下文。它不会自动修改 MEMORY、Profile 或内核；所有长期记忆与规则变化都需要 Human 明确确认。
