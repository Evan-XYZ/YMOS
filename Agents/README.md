# YMOS Agents — 运行时编排层

> 把 YMOS 从「一堆 SOP」升级成「4 个角色 + 一条调度链」。

V3 的做法是：你说一句暗号，AI 去翻对应的 SOP 执行。能跑，但有两个问题——

1. **职责混在一起**：同一个会话既看市场、又做判断、又改状态机，改错了不知道是谁改的。
2. **顺序靠自觉**：没有强制"先有洞察、再有雷达、最后才谈策略"，容易拿着过期的市场判断去做决策。

Agents 层就是来解决这两件事的。它不是新增功能，而是**给已有的 SOP 定角色、定顺序、定边界**。

---

## 先说清楚：这些文件不会自动运行

`Agents/` 是**运行协议**，不是四个常驻进程，也不是复制进目录后就会自动生效的程序。

真正的执行链是：

```text
人或定时任务触发
  → 主控 Agent 读取角色卡 / Playbook
  → 再读取对应 SOP
  → 调用脚本与工具
  → 按角色权限落盘
```

- 没有定时任务时：四个角色只在你手动点名时生效。
- 定时任务只写“读 SOP”时：SOP 会运行，但角色边界主要靠 SOP 自己约束。
- 想让 Agents 层真正起作用：任务提示词必须同时指定**角色文件 + SOP 文件 + 成功判定**。
- 宿主支持真子 Agent 时可以拆成四个执行体；不支持时由一个主控顺序扮演，结果一样遵守同一协议。

## 四个角色

| 角色 | 定位 | 核心产出 |
|---|---|---|
| **Market Insight** | 只负责看市场，不下动作判断 | `Eyes/市场洞察/` |
| **Investment Radar** | 把"市场发生了什么"翻译成"哪些标的值得看" | `Eyes/投资雷达/` |
| **Strategy** | 对单标的或组合做动作级分析 | `Brain/策略分析/` |
| **Portfolio State** | **唯一状态写回者** | `持仓与关注/` 状态机 |

### 两条硬规矩

**① 顺序不能乱**

```text
Market Insight → Investment Radar → Strategy → Portfolio State
   看到什么          跟我有关吗         该怎么办        记下来
```

雷达必须基于当日洞察，策略必须基于当日雷达。跳步 = 拿过期判断做决策。

**② 状态写回只有一个出口**

只有 Portfolio State Agent 能改状态机。其他角色再确信也只能"建议改"，不能自己动手。
这样出问题时永远知道是谁写的，也不会出现两个角色同时改同一个文件。

> 还有一条容易被忽略的：**用户口头说的仓位，优先级高于状态机里的旧记录。**
> 人才是真相源，文件只是人的记账本。

## 文件导航

| 文件 | 什么时候读 |
|---|---|
| `ORCHESTRATION.md` | **先读这个。** 四个角色的完整定义：各自读什么、写什么、何时触发、不能碰什么 |
| `EXECUTION_PLAYBOOK.md` | 每个角色的五段式执行手册（运行前检查 / 标准动作 / 必须写入 / 成功判定 / 禁止动作）+ 四种异常处理 |
| `RUNTIME_MODE.md` | 当前是"单主控扮演 4 角色"还是"真并发子 agent"，以及升级条件 |
| `SCHEDULES.md` | 定时任务链怎么排、依赖关系是什么 |
| `SCHEDULES_REFERENCE.md` | **实战参考**：一套真跑了几个月的配置 + 踩坑约束 + 起步建议 |
| `*-agent.md` | 四张角色卡，每张 4 行。给 Agent 快速加载用 |

## 怎么用

**手动**：跟 AI 说"现在你是 Investment Radar Agent"，让它读 `EXECUTION_PLAYBOOK.md` 里对应的段落，
按五段式跑完。跑完提醒它：状态写回不归你管。

**定时**：照 `SCHEDULES.md` 排任务，每个任务同时指定角色卡和对应 SOP，例如：

```text
先读取 Agents/market-insight-agent.md 与 Agents/EXECUTION_PLAYBOOK.md 中的
Market Insight 段落，再读取 Eyes/SOP_市场洞察.md 并执行。
只写角色允许的目录；通过 SOP 的成功判定后才结束。
```

任何支持定时触发的 Agent 宿主都行——Claude Code、Codex、OpenClaw 都可以。

**现在能做到什么程度**：多数宿主目前只给你一个主控会话，所以是**单主控按顺序扮演 4 个角色**，
不是真并发。这已经足够把编排的好处拿到手了。等宿主支持真子 agent，协议直接映射过去即可，
文档不用改。

## 为什么值得这么做

一个人做投资，最容易出问题的不是判断力，是**流程在压力下变形**：
行情一急，就跳过市场判断直接看个股；亏了一笔，就绕过纪律直接改仓位记录。

把角色和顺序写死，等于给自己装了一道**结构性的减速带**。
它不保证你判断对，但保证你判断的时候，手上拿的是当天的、完整的、按顺序生成的信息。
