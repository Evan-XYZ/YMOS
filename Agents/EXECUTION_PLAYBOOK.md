# EXECUTION_PLAYBOOK.md

> 基准路径：`<你的 YMOS 根目录>`
> 目标：让 YMOS 先以 **可运行** 为第一优先级，在当前 `main` 单主控条件下，稳定扮演 4 个 Agent 角色。

---

## 一、总原则

### 1. 当前运行模式
- **不是** 4 个真子 Agent 并发
- **而是** 1 个 `main` 顺序扮演：
  1. Market Insight Agent
  2. Investment Radar Agent
  3. Strategy Agent
  4. Portfolio State Agent

### 2. 运行优先级
- **先有产出，再谈优雅**
- **先按既定路径落盘，再谈自动化增强**
- **状态写回必须收口到 Portfolio State Agent**

### 3. 唯一路径约束
所有日常产出必须落到：
`<你的 YMOS 根目录>`

---

## 二、角色执行手册

# 1. Market Insight Agent

## 目标
生成当日市场洞察，作为后续 Investment Radar Agent 的前置输入。

## 运行前检查
按顺序确认：
1. `Eyes/SOP_市场洞察.md` 存在
2. `Eyes/scripts/` 可用
3. 当日文件 `Eyes/市场洞察/YYYY-MM/YYYY-MM-DD_市场洞察.md` 是否已存在

## 标准动作
1. 读取最近 1-7 天市场洞察，理解主线演变
2. 读取必要脚本与参考提示词
3. 生成或更新当日市场洞察
4. 确认写入路径正确

## 必须写入
- `Eyes/市场洞察/YYYY-MM/YYYY-MM-DD_市场洞察.md`
- 如有 Raw Data：`Eyes/市场洞察/Raw_Data/YYYY-MM/`

## 成功判定
满足以下任意两项：
- 当日市场洞察文件已存在且内容非空
- 含有市场主线、风险提示、机会梳理三部分
- 文件日期与当天一致

## 禁止动作
- 不直接改 `持仓_状态机.md`
- 不直接生成买卖建议
- 不直接修改个股身份

---

# 2. Investment Radar Agent

## 目标
把“市场发生了什么”翻译成“和当前持仓/Watchlist 有什么关系，下一步该分析什么”。

## 前置依赖
- 当日市场洞察已存在
- `持仓_状态机.md` / `Watchlist_状态机.md` 可读

## 标准动作
1. 读取当日市场洞察 + 最近 7 天洞察
2. 读取上一份投资雷达，保证连续性
3. 读取持仓状态机、Watchlist 状态机
4. 如需要，执行价格扫描
5. 生成桥接报告
6. 给出两类建议：
   - 策略分析建议
   - 调研建议

## 必须写入
- `Eyes/投资雷达/YYYY-MM/投资雷达_YYYY-MM-DD.md`
- 如有价格扫描：`Eyes/投资雷达/Raw_Data/YYYY-MM/`

## 成功判定
报告中至少包含：
- 市场趋势回顾
- 持仓监控
- Watchlist 动态
- 下一步建议

## 禁止动作
- 不直接输出“买/卖执行”
- 不迁移标的身份
- 不作为最终状态写回者

---

# 3. Strategy Agent

## 目标
消费雷达建议或用户直达指令，对标的做动作级分析。

## 触发来源
### A. 用户主动触发
- `调研一下 [ticker]`
- `我想买 [ticker]`
- `我想卖 [ticker]`
- `持有怎么看 [ticker]`
- `做个仓位再平衡`

### B. 定时触发
- 读取当日投资雷达中的“下一步建议”区块

## 标准动作
1. 读取最新投资雷达
2. 读取目标标的文件夹全部上下文
3. 缺 P1/P4/P2 时优先补足
4. 执行对应 P 链
5. 输出策略报告或初始调研结果
6. 如有结论，增量写回知识库 / 备忘录

## 必须写入
- `Brain/策略分析/YYYY-MM/` 下的策略报告（若本次有策略动作分析）
- `持仓与关注/{位置}/名称_TICKER/个股基础知识库.md`
- `持仓与关注/{位置}/名称_TICKER/买入卖出备忘录.md`（若本次属于持有/买卖分析）

## 成功判定
至少满足一项：
- 完成一份初始调研并写回个股知识库
- 完成一份策略分析报告并落盘
- 完成持有/买卖备忘录更新

## 禁止动作
- 不直接改 `当前关注方向与投资偏好.md`
- 不越权修改状态机最终身份
- 不绕过 P12 就输出强动作结论

---

# 4. Portfolio State Agent

## 目标
统一收口：状态机更新 + 人类可读视图生成。

## 前置依赖
- 当日市场洞察 / 投资雷达 / 策略分析 至少已有其中 1 项新增
- 当前状态机可读

## 标准动作
1. 读取最新状态机
2. 读取当天新增的市场/雷达/策略结果
3. 合并用户最新口头仓位信息（如果今天有）
4. 更新：
   - 持仓_状态机.md
   - Watchlist_状态机.md
5. 生成：
   - 持仓备忘录_视图.md（运行看板版）
6. 强制刷新：
   - 今日驾驶舱
   - 缺口清单
   - 今日动作队列（P0/P1/P2）

## 必须写入
- `持仓与关注/持仓_状态机.md`
- `持仓与关注/Watchlist_状态机.md`
- `持仓与关注/持仓备忘录_视图.md`

## 状态机写回最低要求
每次写回必须同时完成：
1. 更新时间
2. 对应标的行更新
3. 变更日志追加

## 成功判定
- 状态机与视图中的持仓数一致
- 今日新增的标的/建议已体现在状态机或视图层
- 没有写到错误路径

## 禁止动作
- 不新增深度市场分析
- 不替代 Strategy Agent 做策略判断
- 不修改投资偏好灵魂文件

---

## 三、四段定时编排的实际执行方式

### 10:30 — Market Insight Agent
动作：
- 只看市场
- 生成市场洞察
- 不碰状态机

### 10:45 — Investment Radar Agent
动作：
- 读取 10:30 产出
- 结合状态机生成桥接报告
- 给出后续建议

### 10:55 — Strategy Agent
动作：
- 消费投资雷达里的建议
- 优先处理：
  1. 明显价格/事件触发的持仓
  2. 已持有但缺档案的标的
  3. 新口头同步但尚未建档的标的

### 11:05 — Portfolio State Agent
动作：
- 统一收口
- 同步状态机
- 生成持仓备忘录视图

---

## 四、异常处理

### 场景 1：当天市场洞察不存在
- Investment Radar Agent 应先回补或触发 Market Insight Agent 逻辑
- 再继续跑雷达

### 场景 2：投资雷达不存在
- Strategy Agent 不直接瞎跑
- 先读取最近一份雷达；若没有，则只处理用户明确指定标的

### 场景 3：用户口头仓位与状态机冲突
- **以用户最新口头同步为准**
- 交由 Portfolio State Agent 统一修正

### 场景 4：子 Agent 当前不可用
- 继续使用 `main` 扮演四角色
- 不阻塞日常运行

---

## 五、当前可运行标准（MVP）
只要满足以下 5 条，就视为系统“可运行”：
1. 每天能生成市场洞察
2. 每天能生成投资雷达
3. 有触发时能推进策略分析/初始调研
4. 状态机能被统一写回
5. 持仓备忘录视图能给人直接看

达到这 5 条之前，不追求炫技，不追求并发，不追求完美自动化。
