# 定时任务参考配置（实战版）

> `SCHEDULES.md` 讲的是**编排原理**；这份给的是**一套真实跑了几个月、迭代过二十多版的具体配置**，作为起步参考。
>
> 直接抄时间没有意义——你的市场、作息、精力分配都不一样。
> 真正值得抄的是**为什么这么排**，以及那几条踩坑踩出来的约束。
>
> 表里带 🔒 的是**作者策略内核扩展**（默认关闭）。通用投研主链先运行市场洞察 + 投资雷达；内核审计要等有足够样本后再启用。
>
> 本文保留了作者长期运行形成的时间安排，但必须区分两件事：公开版 Investment Radar 是 `balanced / price / event` 投研汇总，可读轻量关注文件，不读 Profile；账户熔断、次日交易定调和动作规则属于另行启用的策略 / 操盘扩展。

---

## 一、先看这条时序闭环（整份配置的灵魂）

```text
每个交易日  市场洞察 / 热门观察 ──→ 外部事实与动量线索
                                      ▼
收盘后      投资雷达 ─────────────→ 汇总价格、事件、持仓 / Watchlist
                                      ▼（可选；需 active Profile）
            🔒 策略分析 / 计划 ────→ 个性化判断与 Human 门禁
                                      ▼
            Human 决定是否执行
```

这套排法先保证投研信息在收盘后收口；如果用户另行启用了策略与操盘层，再进一步让“决策”和“执行”在时间上分开。

最初的版本是把投资雷达放在早上 08:30 跑——收盘后不看盘，早上看完雷达就开盘。
结果是每天都在**盘前临时做决策**，然后带着刚出炉的判断冲进开盘的情绪里。

后来把作者自用链的收口任务挪到 **16:45（收盘后）**。公开版可直接借鉴这个时间点来运行 Investment Radar；作者自用的账户曲线体检、连续不盈利熔断和次日定调，则应放在另行启用的策略 / 操盘任务中，不能塞回通用雷达。

> 如果你只从这份文件里拿走一条：**把事实汇总放在收盘后；若启用决策任务，再让它消费已完成的汇总，而不是与开盘情绪同时发生。**

## 二、A 股链路（北京时间）

| 时间 | 任务 | 干什么 | 依赖 |
|:---|:---|:---|:---|
| 08:00 | 市场洞察 | 隔夜外盘 + 宏观 + 新闻 → 市场日报 | — |
| 15:30 | 🔒 What's Hot | 按市场环境选择动量剧本 → 五张发现表 | 市场洞察（近 3–7 天） |
| 16:05 | 🔒 A 股热门观察 | 消费当天 What's Hot → 个人阅读报告与连续剧 | 15:30 What's Hot |
| 16:45 | **投资雷达（投研汇总版）** | 按所选模式汇总市场、热门观察、持仓 / Watchlist、价格与事件 | 上面可用的报告；局部缺失可降级 |
| 次日 09:00 | 🔒 策略分析 / 交易计划 | 消费昨日雷达与当日事实，按个人 Profile 形成待 Human 审阅事项 | 16:45 雷达 + active Profile |

**为什么是 15:30 / 16:05 / 16:45 这三档**：A 股 15:00 收盘，数据落地需要缓冲；
三档之间留 15–30 分钟，是为了让上一环真的写完文件，下一环才有东西可读。
**不要图省事排成同一时刻并发——它们是有依赖的链，不是一组独立任务。**

## 三、美股链路（北京时间，对应美股盘后）

| 时间 | 任务 | 干什么 |
|:---|:---|:---|
| 美股收盘后 | 🔒 美股热门追踪 | 异动 + 新高 + 启动三条观察线 → 归因与 A 股映射 |
| 上游完成后 | 🔒 美股热门观察 | 消费热门追踪 → 资金奖惩与连续剧阅读报告 |

**注意运行日是周二到周六**：美股周一收盘对应北京时间周二凌晨。
这个 off-by-one 很容易配错，配错的结果是周一凌晨跑了个空。

## 四、周日复盘链

| 时间 | 任务 | 干什么 |
|:---|:---|:---|
| 16:00 | 🔒 产业链周度深度 | 维护知识库 + 主线复盘（可选） |
| 19:00 | **平仓复盘归档** | 把本周平仓的单笔提取成证据 → `Brain/内核审计/优化建议/` |

19:00 那个是把操盘层的结果喂回策略内核的入口。**它不改规则，只固定证据。**

真正产出改进建议的是**内核周期审计**——建议月度或季度跑一次，不要每周跑：

| 频率 | 任务 | 干什么 |
|:---|:---|:---|
| 每月 / 每季 | **内核周期审计** | 聚合已归档复盘 → 找重复缺口 → 判断层变更提案 |

**为什么审计要拉长到月度**：样本不足 10 笔时提案没有意义，而每周的样本量通常达不到。
按周跑只会让你在噪音里找信号，然后把运气不好改成规则问题。

## 五、几条踩出来的运行约束

这几条不是设计出来的，是**出过问题之后加的**：

| 约束 | 为什么 |
|:---|:---|
| **只写文件，不回推聊天**（`deliver=local`）| 定时任务往聊天里推消息，会在你专注做别的事时打断你。让它安静写文件，你想看时再看 |
| **按任务收窄工具集** | 数据抓取任务保留必要网络权限；纯汇总任务只给文件与终端。权限范围以 SOP 的数据链为准 |
| **固定 workdir 到 YMOS 根目录** | 不固定的话，相对路径会在不同宿主下解析到不同地方，报告写飞了都不知道 |
| **任务名带前缀**（如 `YMOS - 投资雷达`）| 宿主里任务多了之后，没前缀根本认不出哪些是 YMOS 的 |
| **产出必须做结构校验** | 见 `scripts/validate_market_insight.py`。LLM 偶尔会写出缺段落的报告，没校验就会一路污染下游 |

## 六、什么该停掉

配置迭代到后来，**停掉的任务比新增的更值钱**。停掉的判据只有一条：

> **这个任务的产出，我最近一个月真的看过吗？**

实战里被停掉的典型：

- **每日全量产业链追踪** → 降频到每周一次。每天跑的边际信息量很低，但每天都要花时间扫一眼。
- **窄口径的价格跟踪** → 被更宽的「热门追踪」覆盖，功能重复。
- **每日持仓一致性校验** → 降级为手动兜底（`检查一下持仓`）。它是校验，不是每天都有东西要校验。
- **所有面向"对外交付"的任务** → 如果你的目标是自用，这些纯属自我消耗。

**一个健康的配置，长期启用的任务应该在 4–6 个。** 超过十个，说明你在用定时任务缓解焦虑，
而不是在解决问题。

## 七、怎么落到你自己的宿主上

配置方式取决于你用什么（Claude Code / Codex / OpenClaw / 系统 cron 都行）。
不管用哪个，一条任务需要说清楚四件事：

```text
1. 什么时候跑     cron 表达式，注意运行日（美股链是周二到周六）
2. 在哪跑         workdir 固定到 YMOS 根目录
3. 跑什么         指定 <角色文件> + <SOP 路径> + 成功判定
4. 产出去哪       写文件；不回推聊天
```

提示词模板：

```text
先读取 <你的 YMOS 根目录>/Agents/investment-radar-agent.md，
再读取 Agents/EXECUTION_PLAYBOOK.md 中的 Investment Radar 段落，
最后读取 Eyes/SOP_投资雷达.md 并按步骤执行。
只写该角色允许的目录；确认产物通过 SOP 成功判定后，只回一行完成状态，不要粘贴全文。
```

> 最后一句「不要粘贴全文」很重要。不加的话，每天会收到一大段刷屏。

## 八、起步建议：先跑两条主链，再按使用深度增加

第一次配定时任务，别照着上面全套抄。先让两条投研主链稳定跑两周；如果已经启用操盘层并产生真实平仓，再增加第三条：

| 优先级 | 任务 | 理由 |
|:---|:---|:---|
| 1 | 市场洞察（每个交易日早上） | 最低成本的信息压缩，跑不跑得通一眼看出来 |
| 2 | 投资雷达（每个交易日**收盘后**） | 把全天事实、价格和个人关注收口，形成次日研究入口 |
| 3（启用操盘层后） | 平仓复盘归档（每周或每次平仓后） | 把真实操盘结果变成验证证据；没有平仓时不需要空跑 |

前两条投研主链完全不读 Strategy Profile；第三条平仓复盘在 Profile 缺失时只机械固定计划与实际，不做判断力评价，也不直接改策略。它们先跑起来就有价值。
内核审计要等你攒够样本（建议 ≥ 10 笔平仓）再开始。

两周后你会很清楚：哪份报告你每天都点开，哪份你从来没看过。
**然后再决定加什么、停什么——而不是一上来就配十个。**
