# 入职引导 SOP

> 暗号：`开始使用` / `初始化系统`

## 一句话定位

入职不是一次填完作者偏好问卷，而是按需要完成三件可以分开的事：先跑通投研层，再建立策略内核，最后按需验证操盘层能留下真实证据。

```text
投研层：我需要看见和研究什么
  → 策略内核层：我怎样判断、什么时候认错
  → 操盘层：我怎样计划、确认、执行和留痕
```

## 触发

根据暗号进入不同阶段：

- `开始使用` / `初始化系统`：只要求完成投研层最小入职。
- `配置一下我的内核`：进入策略内核配置，调用内核入职 SOP；新用户默认走快速模式，有旧规则或日志的用户可走完整诊断模式。
- 用户明确要使用交易计划台、买卖决策台或真实交易留痕：进入操盘层配置。

Profile 为 `draft`、Console 未配置、没有持仓或 Watchlist 都不应自动触发整套入职。只补当前缺失部分，不强制重跑其他阶段。

动作级请求遇到 Profile 缺失或仍为 `draft` 时，`kernel_not_ready` 是一个可恢复的运行状态，不是程序报错。Agent 必须先说明“投研层仍可继续”，再询问用户是否现在用几分钟建立最小策略内核；不得只抛状态码，也不得静默套用公共策略。

## Phase 1：投研层最小入职

先确认用户真正需要看到什么，不默认安装所有数据源。

### 1.1 市场与信息范围

询问：

- 主要市场和工具是什么？
- 需要价格、新闻、公告、财务还是其他事实？
- 哪些来源已经可用？哪些完全不需要？
- 数据多长时间后视为过期？

### 1.2 能力自检

检查当前环境可用的脚本、Skills 和 API 配置。输出三栏：

| 已可用 | 可选增强 | 不需要 |
|:---|:---|:---|

不因可选驱动缺失而阻塞最小闭环；必须写明失败降级。

### 1.3 投研清单草案

只生成用户所需的数据、报告和频率，不照搬作者的市场与扩展任务。提醒用户：手动暗号用于试跑；日常持续监测需要在 Agent 宿主中配置定时任务。

### 1.4 最小运行视图

- 只询问市场范围、能力圈、当前持仓和关注，不逼用户填写完整策略参数。
- 初始化持仓 / Watchlist 状态；空仓和无关注都是合法状态。
- 跑通 `市场洞察 → 投资雷达`，确认 Reader 能读取产物。
- 输出后续入口：配置策略内核、增加投研能力、启用操盘层；不自动继续。

完成 Phase 1 后向用户明确给出两条合法路径：

1. **先用投研层**：无需运行 Profile，继续生成事实报告；动作级问题暂不输出个性化结论。
2. **建立我的策略**：说“配置一下我的内核”，由 Agent 逐题访谈并生成个人草案。

系统不提供默认激活的“通用投资策略”。公共预置只允许包含 `draft`、Human 门禁、决策与执行分离等结构不变量，不能包含仓位、止损、周期、市场或裁判的默认答案。

## Phase 2：策略内核配置（用户选择后进入）

调用 `Brain/内核审计/SOP_内核入职配置.md`。

### 2.1 选择快速模式或完整模式

- **快速模式**：适合第一次建立策略。Agent 一次只问一个问题，完成市场与能力圈、入场证据、失效信号、风险期限、加减仓与 Human 门禁六组最小字段。
- **完整模式**：适合从 V3 升级，或已有旧规则、交易日志、复盘与 BrainStorm 的用户。先运行结构诊断，再生成草案。

快速模式不是降低安全门槛：回答不完整时保存为 `draft`；只有必填字段完整且 Human 再次确认，才能激活。

### 2.2 完整模式先诊断结构，不接受自我标签代替证据

除用户当前描述外，优先邀请用户提供 V3 偏好文件、改过的 P/SOP、旧投资日志、复盘记录和 BrainStorm。读取 `Brain/ymos-diagnosis/SKILL.md`，检查：

- 策略是否能复述。
- 入场、认错、仓位与期限是否一致。
- 模糊规则能否改成可观察的失效信号。
- 哪些决定必须在非交易时段完成。
- 用户是否已有不可回溯改写的真相源。

### 2.3 用户填写参数

所有比例、阈值、周期和市场选择都由用户提供。Agent 不得从作者 Profile、案例库或模型常识中补默认值。

### 2.4 生成 Strategy Profile 草案

以 `Brain/策略配置/_模板_策略_Profile.md` 为模板，同时更新兼容视图 `持仓与关注/当前关注方向与投资偏好.md`。

写入前必须展示：

1. 策略一句话。
2. 入场与失效信号。
3. 仓位、风险和期限字段。
4. 证据优先级与节奏。
5. 启用、停用、替换模块。
6. 仍未解决的矛盾和空白字段。

草案确认与激活确认必须分开：

1. 用户确认内容后，才保存 `当前策略_Profile.md` 的 `draft` 运行副本；
2. 必填字段完整且用户再次明确要求启用后，才把状态改为 `active`。

BrainStorm 与旧日志是梳理策略的重要上下文，但不得自动变成生效规则；一次性感悟保留为候选，矛盾内容列为待确认问题。

### 2.5 可选：查看作者扩展

完成通用 Profile 后，向用户展示两条分支：

1. 只使用 YMOS 通用主闭环；
2. 查看作者公开的默认关闭扩展，包括 P17、P18、P9+P17 专项调研、What's Hot、美股热门追踪、两份个人阅读报告和配套扫描脚本。

第二条只是进化方向和配置样本，不是系统推荐。用户需要先阅读 `Brain/策略配置/examples/author-profile/README.md` 与 `module-manifest.example.json`，逐项确认适用市场、证据源、参数、依赖和 Human 门禁。未明确选择的模块保持关闭。

## Phase 3：操盘层配置（按需）

### 3.1 初始化操盘状态

- 配置分币种账户与资金期限。
- 添加现有持仓和 Watchlist；空仓/无关注都是合法状态。
- 确认买卖决策状态机可由本地 Console 生成。

### 3.2 本地写入测试

正式模式必须从 `Console/server.py` 打开。完成一次不涉及真实交易的测试：

1. Reader 能读取一个 Markdown。
2. 交易计划台能生成测试计划。
3. 买卖决策台能创建测试决策并写入测试 vault。
4. 页面刷新后仍能从 Markdown 恢复，而不是只靠浏览器缓存。

测试数据必须明确标记并由用户决定是否删除。

### 3.3 Human 边界确认

向用户确认：

- Agent 不代替用户下单。
- Agent 不伪造“已执行”的计划、成交或审计记录。
- Strategy Profile 和判断层变更必须由 Human 批准。

## Phase 4：生成当前阶段结果

输出：

- 投研清单与失败降级。
- 若已进入策略内核阶段：已确认的 Strategy Profile、上下文来源和未填字段。
- 若已进入操盘阶段：Console / Markdown 连通状态。
- 启用与停用模块。
- 下一步最小动作，不推荐一次配置所有自动任务。

若用户选择作者扩展，Day 0 只把所选模块记录为“待手动验证”，不直接加入调度。至少完成一次手动运行并检查数据缺失、输出路径和失败降级后，才允许用户自行配置定时任务。

## Day 0 不做什么

- 不替用户选择策略流派。
- 不替用户设置仓位、止损和期限。
- 不用作者个人工作流当默认答案。
- 不因用户选择“查看作者扩展”而批量启用模块或复制作者参数。
- 不在缺少历史记录时声称已经定位用户真正的行为拦截点。
- 不自动修改 P 系列、SOP 或 Console 门禁。
- 不因为 Profile 仍为 `draft` 就阻塞投研层事实流程。
- 不因为用户暂时不用操盘层就认定入职未完成。
