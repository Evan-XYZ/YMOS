# 🏷️ 标的管理 SOP

> 暗号：`关注 XXX` / `建仓 XXX` / `移除关注 XXX` / `清仓 XXX`
> 模块：持仓与关注/（状态层）

---

## 一句话定位

标的管理做两件事：**维护「持仓与关注」的状态真相源** + **触发初始调研（同步或异步）**

- 关注 = 创建目录 + 初始化文档 + 智能触发初始调研
- “建仓”只建立候选建仓身份和研究上下文，不代表成交；真实持仓只能由 Console `fill` 事件产生
- 初始调研的实际执行由 `Brain/SOP_初始调研.md` 负责

---

## 🔑 触发暗号

| 暗号 | 动作 | 说明 |
|:---|:---|:---|
| `关注 [ticker/名称]` | 新增到 Watchlist + 触发初始调研 | 询问是否立即调研，否则异步 |
| `建仓 [ticker/名称]` | 从 Watchlist 进入候选建仓 | 前置检查 + 决策入口，不产生真实持仓 |
| `移除关注 [ticker/名称]` | 从 Watchlist 归档 | 状态迁移 + 归档 |
| `清仓 [ticker/名称]` | 核对真实 `close` 后归档（保留观察） | 未有 `close` 时只引导进入卖出门禁 |

---

## ⚙️ 执行步骤

### 动作 A：关注（新增 Watchlist + 触发初始调研）

**Step 1：确认标的信息 + 自动补全 Ticker 后缀**

- 解析 ticker（如 `NVDA`、`腾讯`、`BTC`、`688048`）
- 确认市场（US/A股/H股/Crypto）
- 确定目录名格式：`名称_TICKER`

**A股/港股 Ticker 后缀自动识别规则**：

| 代码特征 | 交易所 | Yahoo 后缀 | 示例 |
|:---|:---|:---|:---|
| 6位数字，`6` 开头 | 上交所 | `.SS` | `688981` → `688981.SS` |
| 6位数字，`0` 或 `3` 开头 | 深交所 | `.SZ` | `300274` → `300274.SZ` |
| 4-5位数字（港股） | 港交所 | `.HK` | `700` → `0700.HK` |
| 纯英文字母（美股） | NYSE/NASDAQ | 无后缀 | `NVDA` |
| Crypto | 去中心化 | 无后缀 | `BTC` |

**Step 2：创建文档目录**

```bash
mkdir -p "持仓与关注/动态Watchlist/名称_TICKER"
```

**Step 3：初始化文档**

从模板创建：
- `持仓与关注/_模板_单标的/个股基础知识库.md` → `个股基础知识库.md`
- Watchlist 不创建旧买入卖出备忘录；需要动作留痕时进入 V4 买卖决策台

> 若模板不存在，创建最小骨架文件

**Step 4：写入状态机**

在 `持仓与关注/Watchlist_状态机.md` 新增一行：
- Ticker、名称、市场、加入日期、状态（关注中）
- P4 摘要留空；P2 或其他策略字段只在 Profile 已启用时填写

**Step 5：触发初始调研（智能切换）**

| 场景 | 行为 |
|:---|:---|
| 单个关注（`关注 NVDA`） | 询问用户：「是否现在跑初始调研？」→ 是则同步调用 `Brain/SOP_初始调研.md`，否则异步 |
| 批量关注（一次多个标的） | 第一个询问，其余异步（投资雷达下次会建议调研） |

> 异步 = 投资雷达报告的「调研建议」区块会捕获未建档标的，自然形成调研触发。

**Step 6：在对话中确认**

```
✅ 已关注 [名称]（[TICKER]）
- 目录：持仓与关注/动态Watchlist/名称_TICKER/
- 个股基础知识库已初始化
- Watchlist 状态机已更新
- [初始调研已完成 / 初始调研将在下次投资雷达中触发]

💡 下一步建议：
- 如需立即调研 → 说「调研一下 [TICKER]」
```

---

### 动作 B：建仓（Watchlist → 候选建仓）

**前置**：标的必须已在 Watchlist 中，且 P1+P4 事实底座已完成；其他模块按 Profile 守卫检查

**Step 1**：检查前置
- 确认 `动态Watchlist/名称_TICKER/个股基础知识库.md` 存在且有 P1+P4；Profile 启用的其他前置模块也必须有结果
- **若标的不在 Watchlist**：自动先执行「动作 A：关注」完整流程
- **若缺少 P1/P4 或已启用的前置模块**：调用 `Brain/SOP_初始调研.md` 补跑；停用模块不得强制补跑

**Step 2**：保留在 Watchlist，标记“候选建仓”

在 Human 尚未通过 Console 确认实际成交前，不迁移到 `持仓/`，也不增加 Active 持仓数。

**Step 3**：进入 V4 买卖决策
- 引导 Human 打开买卖决策台创建 `Brain/买入卖出决策/` 单笔计划；不初始化旧 `买入卖出备忘录.md`

**Step 4**：更新状态机
- `Watchlist_状态机.md`：标记「候选建仓」
- `持仓_状态机.md`：不改；只有 Console `fill` 后由 Portfolio State 新增真实持仓

**Step 5**：确认
```
✅ [名称]（[TICKER]）已进入候选建仓
- 研究目录仍在：持仓与关注/动态Watchlist/名称_TICKER/
- 尚未形成真实持仓
- 下一步：执行「我想买 TICKER」进入策略分析；Human 确认成交后再迁移
```

---

### 动作 C：移除关注（Watchlist → 归档）

**Step 1**：归档目录
```bash
mkdir -p "持仓与关注/动态Watchlist/_archive"
mv "持仓与关注/动态Watchlist/名称_TICKER" "持仓与关注/动态Watchlist/_archive/名称_TICKER"
```

**Step 2**：更新 `Watchlist_状态机.md`（标记「已归档」+ 日期）

---

### 动作 D：清仓（持仓 → Watchlist 保留观察）

**Step 0：先核对真实退出**

- 单笔决策文件必须已存在 Console `kind: close` 事件并位于已平仓目录。
- 若尚未平仓，停止身份迁移，引导 Human 运行“我想卖 [ticker]”并在 Console 完成真实退出；不得用一句“清仓”伪造成交。

**Step 1**：核对通过后迁移到 Watchlist
```bash
mv "持仓与关注/持仓/名称_TICKER" "持仓与关注/动态Watchlist/名称_TICKER"
```

**Step 2**：更新状态机
- `持仓_状态机.md`：移除或标记「已清仓」
- `Watchlist_状态机.md`：新增，状态「观察中（已清仓）」

**Step 3**：引用 Console `close` 事实事件；本 SOP 不补写或改写交易历史

**Step 4**：生成复盘提醒
- 在 `持仓与关注/投资复盘/` 下创建 `YYYY-MM-DD_TICKER_清仓复盘.md`

## ⚠️ 边界

- 标的管理的**分析部分由初始调研子模块 SOP 负责**
- 建仓暗号只产生候选身份，**不包含买卖决策或真实成交**
- 目录命名统一为 `名称_TICKER`，价格扫描只认状态机 Ticker 列
- V4 不再为候选建仓初始化旧买入卖出备忘录；以 Console 单笔生命周期文件为准
