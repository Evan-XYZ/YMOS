> 暗号：`跑一下核心资产动态判定表` / `刷新核心资产库` / `A类资产巡检`

## 一句话定位

**核心资产动态判定表 = A/B 资产库的周度巡检面板 + 手动深研后的状态机更新入口。**

热门追踪负责发现“市场正在交易什么”；自动建档负责补齐资料；本 SOP 负责把已经进入观察池的 A/B 资产沉淀成一张动态表：

```text
A/B 资产库（静态 Q1-Q5）
  + 当日/近 7 天市场洞察（基本面事件）
  + 美股热门 / A股 What's Hot（价格事件）
  + 当前价格、1周/1月/52周涨幅、估值变化
  + P17 Q6 势能阶段刷新
= 周度核心资产动态判定表
= 本周哪些资产值得重点看、哪些只是等回调、哪些应降级
```

核心共识：**A 类资产 ≠ A 类买点**。

- A 类资产：长期核心资产或高赔率战略稀缺资产，必须进入资产库长期盯。
- 当前机会：由 Q6、P9 安全边际、价格事件和催化共同决定，可能是 `🚀 抢筹初期`，也可能是 `👀 待回调`。
- B 类资产：资产质量弱于 A 类，但可以因估值 gap、事件催化、主题发酵进入价格跟踪。

### 统一链路契约（2026-05-11）

本 SOP 负责链路最后一段：**资产库治理 + 周度升降级 + 当前机会刷新**。它不是每日热门发现器，也不是买卖指令生成器。

```text
核心资产库 / 美股观察 / A股观察 / 持仓 / 动态 Watchlist
  + 最近 7 天基本面事件（市场洞察 / Finnhub / 公告 / 财报 / 研报 / 新闻）
  + 最近 1-3 份价格事件报告（美股热门 / What’s Hot）
  + 当前价格与估值快照
  → 刷新 P17 Q6 + P9 赔率约束
  → 输出本周：重点看 / 等回调 / 补证据 / 降级移除
  → 写回核心资产状态机与 pending_review
```

关键口径：
- 热门追踪解决“市场在交易什么”；核心资产动态判定表解决“哪些资产值得长期占用注意力”。
- 已经涨了很多的 A 类资产，不能因为涨幅大直接放弃；必须重答 `Q5 终局空间` 与 `Q6 势能阶段`。
- 也不能因为短期热门就把题材股抬进核心资产库；必须有 Q1/Q4/Q5 与 P9 支撑。
- 周度表的价值是帮你减少脑力占用：把“本周真正需要你亲自判断的 3-7 个标的”挑出来。

## 资产等级定义

| 等级 | 定义 | 默认系统动作 |
|:---|:---|:---|
| 🟢 A类核心资产 | 有清晰利润池、份额捕获、可长期复盘的行业龙头 | 自动建档；进入核心资产库；动态判定表每周刷新/手动刷新 |
| 🟣 A类高赔率资产 | 战略稀缺、终局空间大，但估值或执行验证更敏感的资产 | 自动建档；进入核心资产库；重点跟节点/估值击球区 |
| 👀 B类跟踪资产 | 值得盯、但优先级低于 A 类的资产 | 进入观察池；Human 或连续入池后价格跟踪/建档 |
| 🟡 P2观察 | 信号不够连续或证据不足 | 只在日报记录，连续入池或新催化再升级 |
| 🔴 跳过 | 非核心、纯噪音、估值/催化失效 | 不入库 |

## 执行步骤

### Step 1：读取资产池

合并以下来源并去重：

1. 核心资产状态机中的 A/B/P2 资产；
2. 美股观察 / A股观察状态机中的 A/B 候选；
3. 持仓与动态 Watchlist 中已有标的；
4. 最近热门追踪中新晋 P0/P1 但尚未入库的标的。
5. 手动 P9/P17 深研报告中明确建议纳入核心资产库或降级观察的标的。

> 口径优先级：手动深研 / 自动建档后的 P9+P17 复核 > 核心资产动态判定表 > What’s Hot / 美股热门初筛。热门追踪解决“市场在交易什么”，但不直接等于最终核心资产判定。

### Step 2：拆分静态层与动态层

| 层 | 字段 | 更新频率 |
|:---|:---|:---|
| 静态层 | Q1-Q5 压缩摘要、资产等级、核心证据、失效条件 | 初次建档 + 财报/重大事件后 |
| 动态层 | 当前价格、1周/1月/52周涨幅、估值变化、Q6 阶段、当前机会标签 | 每次运行 |

### Step 3：拉价格与估值快照（复用投资雷达价格路由）

价格层不要临场发挥，固定复用投资雷达的三源分流链路：

```bash
cd "<你的 YMOS 根目录>"
mkdir -p "Eyes/核心资产动态判定表/Raw_Data/$(date +%Y-%m)" \
         "Eyes/核心资产动态判定表/$(date +%Y-%m)"

python3 Eyes/scripts/price_scan_core_assets.py \
  --date-tag "$(date +%Y%m%d)" \
  --output-dir "Eyes/核心资产动态判定表/Raw_Data/$(date +%Y-%m)"
```

> 注意：路径含空格必须整体加双引号；不要尝试编辑路径里的空格，原样保留即可。

**脚本职责：**
- 读取 `核心资产状态机.md` + 美股/A股观察状态机 + 持仓/Watchlist 状态机中的 ticker；
- 调用 `Eyes/scripts/fetch_price_router.py`；
- 路由规则与 `SOP_投资雷达.md` 完全一致：

| 市场 | 数据源 | 条件 |
|:---|:---|:---|
| 美股 / Crypto | Finnhub | 有 `FINNHUB_API_KEY` |
| A股（.SS / .SZ） | Tushare | 有 `TUSHARE_TOKEN` |
| 港股（.HK） | Yahoo Finance | 免费 |
| 兜底（无 Key / 专源失败） | Yahoo Finance | 所有市场回退 |

**Raw 输出：**
- `Eyes/核心资产动态判定表/Raw_Data/YYYY-MM/price_scan_finnhub_YYYYMMDD.json`
- `Eyes/核心资产动态判定表/Raw_Data/YYYY-MM/price_scan_tushare_YYYYMMDD.json`
- `Eyes/核心资产动态判定表/Raw_Data/YYYY-MM/price_scan_yahoo_YYYYMMDD.json`

**正式报告至少提炼：**当前价、市值、1周涨幅、1月涨幅、52周区间、PE/PS/EV/EBITDA（可得则写）。若某估值字段缺失，不阻塞报告，但必须标记 `估值字段缺失`。

### Step 4：读取市场洞察与价格事件

对每个资产标记：

- 最近 7 天是否有基本面事件；
- 是否命中美股热门/What's Hot 异动池、新高池、跌幅池；
- 是否与当前主线共振（AI 基建、存储、电力、商业航天、端侧 AI、软件/云等）；
- 是否出现退潮信号。

### Step 5：刷新 P17 Q6 与当前机会标签

Q1-Q5 默认沿用状态机/单标的档案；只在有重大新信息时更新。

Q6 必须重新判断：

- 🌱 萌芽/早期：剩余空间/已涨幅仍高，机构认知未铺满，财报/订单刚开始验证。
- 🌿 加速/中期：主流市场已接受，业绩兑现与股价同步扩散。
- 🍂 成熟/末期：3-5 年预期大部分 price in，需要回调或新催化。
- 🧊 衰退/失效：主逻辑转弱或兑现失败。

当前机会标签：

| 标签 | 解释 | 动作 |
|:---|:---|:---|
| 🚀 抢筹初期 | A类资产 + Q6 早期 + P9 未透支 + 催化清晰 | 本周重点看，必要时触发 P5/P12 |
| 👀 待回调 | A/B资产但涨多或 P9 安全边际不足 | 放入价格跟踪，等击球区 |
| 🟡 Conditional | 证据/估值/执行缺口大 | 补研究，不进买入链 |
| 🔴 降级/移除 | 逻辑失效或非核心 | 从核心资产库降级 |

### Step 6：输出判定表

报告必须包含：

```markdown
## 前置输入完整性
- AI 产业链周日深度版：✅ 已读取 / ⚠️ 缺失（说明本周 AI 链复盘盲区）
- 最近市场洞察：N 份
- 美股热门追踪：N 份
- A股 What's Hot：N 份
> 任一前置缺失时显式标注，避免读者误以为判定表是"满血输入"产出。

## 本周重点
- 🚀 本周可进入买入链评估：...
- 👀 重点等回调：...
- 🟡 需要补证据：...
- 🔴 降级/移除：...

## A类资产动态表
| Ticker | 名称 | 资产等级 | 静态 Q1-Q5 | 当前价/市值 | 1W/1M/52W | P9赔率 | Q6阶段 | 当前机会 | 今日证据 | 后续观察 |

## B类资产动态表
| Ticker | 名称 | 资产等级 | 为什么不是 A | 当前价/市值 | 价格事件 | Q6阶段 | 当前机会 | 升级条件 | 降级条件 |

## 资产升降级建议
| Ticker | 从 | 到 | 原因 | 需要 Human 决策 |
```

### Step 7：状态机写回

- **写入策略**：以 `ticker` 为主键 patch，**不 overwrite 整张表**。Human 注释字段（决策意见、个人笔记、`human_note`、`decision`）只读不写，避免周更覆盖人工沉淀。
- 新 A 类资产：加入 `核心资产状态机.md`，标记 `asset_grade=A_core/A_high_odds`。
- B 类连续 3 次入池或 P17/P9 改善：写入 `pending_review: upgrade`，下周判定表自动重读这个字段。
- A 类 Q6 连续进入 🧊 或 Q2/P9 显著透支：写入 `pending_review: downgrade`。
- 若手动 P9/P17 复核与 What’s Hot 初筛不一致，必须保留两套口径：在观察状态机里保留 `Agent评级`，在核心资产状态机里写最终 `资产等级`；不要用热门初筛覆盖深研结论。
- 对 A股观察池，允许出现“B/P1 → A类核心资产”的反向升级（例如资产质量/赔率优于当天热门排序），也允许出现“A/P0 → B类验证观察”的降级（例如方向稀缺但利润/现金流/估值证据不足）。
- `pending_review` 仅由 Human 决策后清空（写 `null` 或删除字段）；周更只新增/维持，不主动清。
- 只写状态，不替 Human 做最终买卖。
