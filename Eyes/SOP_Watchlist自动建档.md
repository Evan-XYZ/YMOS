> 暗号：`跑一下Watchlist自动建档` / `自动建档` / `批量建档` / `自动调研观察池` / `观察池优先级排序`
> 模块：Eyes → Brain → 持仓与关注

## 一句话定位

**Watchlist 自动建档的主职能从“逐个标的自动深度建档”调整为“每天横向审计观察池，找出当前最值得进入买入链/深研链的核心资产优先级”。**

也就是说：

- 自动任务仍然维护 `美股观察/`、`A股观察/` 的观察池状态机；
- 仍然可以为真正值得纳入 A 类资产库的标的创建“观察壳”文件夹，避免后续丢失；
- **但默认不再对每个 A 类候选逐个跑完整 P1/P4/P2/P9/P17 深度调研**；
- 默认产物改为一份横向报告：**当天/当批观察池里谁是核心资产、谁有应得价值差、谁有当前势能、谁有资金认可、谁处在业绩上修/raise-and-beat 正循环里、谁最值得你手动深研或进入买入链。**

新链路：

```text
美股热门追踪 / A股 What’s Hot
  → A/B 类资产候选 + 当前价格事件
  → 写入 美股观察 / A股观察（Human-in-the-loop 中转层）
  → 自动建档 SOP 消费最新观察池/状态机
  → 横向 P17×P9×Q6×Q7×Raise-and-Beat 优先级排序
  → 输出“当前可进入买入链/深研链”的 Top list
  → 仅为 A_core / A_high_odds 标的创建观察壳 + 状态机指针
  → Human 选择 1-3 只最感兴趣标的，再手动跑 P9/P17 深度调研或 P5/P12 买入链
```

核心纪律：

- **A 类资产不等于当前买点。** 自动任务要先告诉你“谁值得看”，再告诉你“现在值不值得行动”。
- **热门追踪是研究任务派发器，不是买入信号。** 涨停/新高只说明市场在表达，不说明应得价值足够。
- **自动建档不是流水线论文机。** 与其产出 10 份浅调研，不如每天产出 1 份能指导注意力分配的横向优先级报告。
- **深度调研改为 Human 选择后的手动动作。** 你对最感兴趣的公司再跑 P9/P17/P5，质量会比批量自动深研更高。

## 统一链路契约（2026-05-14 v3.1）

本 SOP 负责链路第三段：**观察池横向审计 + 核心资产优先级排序 + 观察壳建档**。

2026-06-02 补充：横向排序时引用 `BrainStorm/`（思考沉淀层）（你自己的框架文件），作为 P17×P9 之后的交易仓/Watchlist 分层增强层。它不替代 P17/P9，只用于回答“谁不仅逻辑好，而且更像趋势资产”。

```text
趋势资产 = 业绩右侧 + 产业右侧 + 股价右侧
三因子 = 业绩因子（连续 solid / raise-and-beat）+ 卡位因子（当下赛道势能）+ K线因子（流畅趋势 / 资金表达）
```

```text
观察池状态机 / 最新观察池日报
  → 去重：持仓 / 动态 Watchlist / 已有单标的档案 / 手动调研已完成的潜在观察
  → 候选全集：A 类 + B 类 + 连续入池/明显价格事件标的
  → 主线代表权 / 龙头组审计：中军 / 弹性 / 低估值补涨 / 二线价格发现 / Choke Point
  → 轻量事实抓取：财务快照 / 公告事实 / 研报叙事 / 新闻事件 / 行情动量 / 业绩上修轨迹
  → 横向打分：P17 核心资产 + P9 应得价值 + Q6 当前势能 + Q7 股性资金认可 + Raise-and-Beat 业绩上修势能
  → 配置属性审计：InstitutionalCapacity / 大资金容量 / 主仓配置属性
  → 输出“核心资产优先级报告”
  → A_core / A_high_odds 建观察壳并更新状态机
  → Top 1-3 给 Human：建议手动深研 / 进入买入链 / 等回调 / 跳过
```

执行边界：

- 默认不跑 P5/P12，不替 Human 下单。
- 默认不批量生成完整 `YYYY-MM-DD_[Ticker]_初始调研.md`。
- 默认不把所有 A 类塞进 `动态Watchlist/`。
- 默认只创建“观察壳”：`个股基础知识库.md` 可包含来源、结论摘要、优先级报告链接、后续待补，不冒充完整深度调研。
- 只有 Human 明确说“对 X 跑 P9/P17 深度调研 / 调研一下 X / 进入买入链 / 补正式观察档”，才启动单标的深度 SOP。

## ⚙️ 完整执行步骤

### Step 0：读取输入，消费观察池而不是直接消费原始 Raw

读取优先级：

1. `持仓与关注/美股观察/美股Watchlist状态机.md` / `持仓与关注/A股观察/A股Watchlist状态机.md`；
2. `持仓与关注/美股观察/` 或 `持仓与关注/A股观察/` 最新观察池日报；
3. 最近几份 What's Hot 报告中的 `sis` 段 → 触发 Step 2.4 组级别 P17-lite 研究裁决；
5. 用户显式指定的 ticker/代码；
6. 必要时读取上游热门追踪正文与 Raw 数据，补价格事件来源。

候选全集规则：

- 必须纳入：状态机或日报里的 A 类/P0 候选；
- 应该纳入：B 类里涨停、新高、连续入池、明显处于主线扩散位置的候选；
- 可以纳入：Human 指定的候选；
- **强制纳入横向审计**：上游 What’s Hot 输出的 `mainline_groups` 成员，尤其是中军/定价锚、弹性龙头、低估值补涨、二线价格发现；即使原始评级只是 B/P1，也必须纳入主线组比较；
- 默认排除：已明确 Block、旧 Beta、纯风险提醒、无可验证主线的噪声票。

> 关键变化：横向优先级报告要看“全池谁最值得买/深研”，不能只看原始 A 类标签。5 月 10 日大族激光原本在 B 类，但横向 P17×P9 后反而是最接近买入链的标的，这就是新 SOP 要固化的能力。

### Step 1：去重与身份判断

去重检查：

- 已在持仓 → 不新建观察壳；报告里标记为“持仓复核 / 走 P6/P7”；
- 已在动态 Watchlist → 不重复建档；报告里引用现有路径；
- 已在观察池单标的目录 → 增量更新 `个股基础知识库.md` 的“优先级报告索引”；
- 已在 `持仓与关注/手动调研/感兴趣的潜在观察标的.md` 完成过手动 P9/P17 → 默认引用手动报告，不重复跑；
- 新晋 A_core / A_high_odds → 可创建观察壳。

手动调研防重规则沿用旧版：

1. 以 ticker 为主键，A 股兼容 `300751` / `300751.SZ` / `300751.SH`；
2. 同时检查 YAML `items[].status` 与 `## 已完成` 表格；
3. 已完成且有 `report_path` 的，报告引用它；除非 Human 明确要求，不再自动深研。

### Step 2：轻量事实抓取，不做逐标的长文调研

横向排序必须有事实输入，但不要求每只都生成 8k+ 深度报告。

#### 美股最小输入

- 最新价格、市值、20/60/120 日涨跌幅、新高位置、成交量；
- 最近 10-Q/10-K/8-K/IR release 的收入、毛利率、经营利润、现金、债务、RPO/backlog/订单口径；
- 最近 2-4 个季度的 beat / miss、guide up / guide down、分析师预期上修 / 下修轨迹；
- 1-3 个 Anchor Comparable；
- 近期催化：财报 beat/raise、客户长约、NVIDIA/Meta/云厂商合作、产品代际、CapEx 流向。

#### A 股最小输入

优先使用问财四层：

```bash
cd "<你的 YMOS 根目录>"
python3 Eyes/scripts/iwencai_finance_query.py "股票名 最新一期 营业收入 净利润 毛利率 净利率 ROE 资产负债率 经营现金流" -l 3
python3 Eyes/scripts/iwencai_announcement_search.py "股票名 最新一季报 年报 业绩预告 公告" -l 8
python3 Eyes/scripts/iwencai_report_search.py "股票名" -l 5
python3 Eyes/scripts/iwencai_news_search.py "股票名 核心业务 最新新闻" -l 8 --days 30
```

额外补一层 **Raise-and-Beat / 业绩上修势能**：

- 最近 2-4 个季度收入、利润、毛利率、订单/在手订单是否连续超预期；
- 业绩预告、管理层指引、研报一致预期是否持续上修；
- 同赛道多只都算核心资产时，优先选择“业绩越来越好 + 预期持续上修”的标的。

写报告时要区分：

- 财务 / 公告 = 事实层；
- 研报 = 市场叙事与估值锚；
- 新闻 = 最新事件与传播线索；
- 行情 = Q6/Q7 的资金表达证据。

如果数据源降级，必须在报告里写清：哪些字段是 hard fact，哪些只是线索。

### Step 2.4：板块首发信号先手裁决（组级别 P17-lite · 2026-07-01 新增）

**优先级最高、先于逐只排序执行。** 读取当期及近期 What's Hot 报告的 `sis` 段：

- 若存在 active SIS → 对每个板块跑一次**组级别 P17-lite**（提示词见 `Brain/references/p17-core-asset.md` §0.7），输出「组级别 P17-lite 先手裁决卡」，写入报告 `## 0.6 组级别 P17-lite 先手裁决`（位置：结论先行之后、击球区命中之前）。
- 裁决卡五步：主线确认度 → 代表权分工（中军/弹性/choke/补涨）→ 势能阶段 → 先手动作 → 驳回信号。
- **先手动作纪律**（与逐只排序解耦）：
  - 初期/中段 且 代表权在击球区/贴近 → 建议 Human 对**中军**跑快速 P5（含 Q5 信念测试）+ P12，先手观察/试错仓；
  - 加速后段 → 只在报告中登记代表权与待验证条件，不生成买入动作；
  - 一次只放行 1-2 只（优先中军），不摊全组。
- 将 `stage / verdict / next_review` 写入本期排序报告；后续报告通过日期和主题键串联，不维护独立注册表。
- **关键**：这是"先定代表权"的先手层，不替代 Step 3 逐只排序；SIS 板块的代表权仍会在总排序表出现，但先手裁决让 Human 当天就能对中军动手，不必等逐只深研跑完。

### Step 2.5：主线代表权 / 龙头组横向审计

如果上游 What’s Hot 输出了 `mainline_groups`，或观察池中同一主题 2-3 个交易日连续出现 movers / newhighs / wide-newhighs，则本 SOP 必须先做一段组内审计，再进入单票综合排序。

目标：回答 **“市场买这个方向时，第一组会买谁？”** 而不是只回答“哪只票财务最漂亮”。

> 与 Step 2.4 的关系：Step 2.4 处理**已触发 SIS 的板块**（硬信号 → 先手裁决）；Step 2.5 处理**未达 SIS 但有龙头组结构**的软预警（横向审计 → 深研排序）。SIS 板块直接走 2.4 先手，不必在 2.5 重复。

#### 2.5.1 龙头组分层

| 角色 | 定义 | 审计重点 |
|:---|:---|:---|
| 中军 / 定价锚 | 大市值、高流动性、机构可配置，市场解释主线绕不开 | 是否有主线代表权、容量、带动性、边际重估 |
| 弹性龙头 | 主线里业绩/叙事/股性弹性最大，常承担右侧加速 | Q6/Q7、产品/客户催化、估值弹性 |
| 低估值补涨 | 主线已确认后，资金寻找低估值/低位修复 | 估值 gap、盈利修复、是否只是补涨 |
| 二线价格发现 | 次新/小市值/二线环节，先于基本面被交易 | 是否只是温度计，还是可转入深研 |
| Choke Point / 漂亮环节 | 设备、材料、载板、软件、耗材等稀缺环节 | P17 Q4 稀缺性、议价权、非对称收益 |

#### 2.5.2 RepresentativeRight / 主线代表权因子

该因子默认不直接改变综合分，但可以**强制入审计名单**，并影响“今日深研链 Top 1-3”的注意力分配。

```text
RepresentativeRight / 主线代表权 = 0-100
```

检查项：

- 是否是板块中军/定价锚；
- 是否能承载机构仓位；
- 是否是市场解释该主线时绕不开的名字；
- 是否一涨能带动同组资产；
- 是否有边际重估逻辑，即使静态毛利率低。

#### 2.5.3 低毛利制造龙头边际重估模板

对封测、代工、服务器、整机、制造服务类公司，不允许只用静态毛利率/净利率降权。必须检查：

1. 稼动率是否修复；
2. 高端产品收入占比是否提升；
3. AI/HPC 客户或订单是否改善 ASP / mix；
4. 固定成本摊薄是否带来经营杠杆；
5. 毛利率/净利率是否有边际改善；
6. 是否具有机构容量与主线解释权。

裁决标签：

- `data_miss`：上游 Raw 没看见；
- `escalation_miss`：Raw/What’s Hot 已看见，但没有及时升权成龙头组审计；
- `valuation_veto`：已审计，但 P9 赔率/估值不支持；
- `evidence_gap`：价格强，公告/财务/客户证据不足；
- `temperature_only`：仅作板块温度计，不进买入链。

示例：先进封装 / OSAT 应先横向审计 `长电科技 / 通富微电 / 华天科技`，再比较 `甬矽 / 盛合 / 伟测` 的弹性和 `深南 / 联瑞 / 安集 / 芯源微 / 中科飞测` 的 Choke Point 价值。不能只因为封测毛利低，就跳过市场已经买出来的平台型中军。

### Step 3：横向 P17×P9×Q6×Q7×Raise-and-Beat 优先级排序

每个候选都输出核心四维 + Raise-and-Beat + Evidence，不再只给 A/B 标签。若存在 `mainline_groups`，还必须输出 RepresentativeRight 与组内角色；RepresentativeRight 可以强制入审计名单，但不替代 P17/P9/Q6/Q7。自 2026-05-27 起，所有核心资产优先级报告还必须输出 `InstitutionalCapacity / 大资金容量 / 配置属性`，用于判断该资产适合主仓配置、试验仓非对称，还是只作温度计。

| 模块 | 权重 | 回答的问题 | 核心证据 |
|:---|---:|:---|:---|
| P17 核心资产分 | 32% | 它是不是赛道核心、稀缺、能捕获份额、终局空间够不够？ | Q1/Q3/Q4/Q5 |
| P9 应得价值 / 赔率分 | 28% | 当前价格相对“应得价值”是否仍有差额？ | Anchor Comparable、反向估值、Bear/Base/Bull 区间 |
| 潜在收益分级 | 参考项 | 这是一档 A1/A2/A3/A4/A5 机会，还是暂不分级？ | P9 Base/Bull/Blue Sky 空间、P17 Q5/Q6/Q7、兑现周期 |
| Q6 当前势能分 | 13% | 为什么是现在看？是早期抢筹、中期扩散还是末期拥挤？ | 财报/订单/产业事件/传播阶段 |
| Q7 股性资金认可分 | 12% | 市场是否愿意用钱表达？同赛道里它是不是交易抓手？ | RS、上涨捕获、回撤修复、量价、事件反馈 |
| Raise-and-Beat 业绩上修分 | 10% | 这家公司是不是处在“业绩越来越好、预期持续上修”的路上？ | 连续 beat、guide up、订单/backlog 上修、毛利率改善、分析师预期上调 |
| 证据强度 / 反证分 | 5% | 结论是不是有硬证据支撑？有没有关键反证？ | 公告、SEC/IR、财报、数据完整度 |
| RepresentativeRight / 主线代表权 | 强制审计项 | 市场买这个方向时，第一组会买谁？它是否承载配置权？ | 龙头组角色、流动性、市值容量、带动性、边际重估 |
| InstitutionalCapacity / 大资金容量 | 配置属性项 | 如果管理 10 亿资金配置这个方向，会不会买它？它能否作为主仓配置资产？ | 市值、成交额、流动性、机构解释成本、指数/基金可配置性、板块 Beta 代表权 |

综合分：

```text
buy_chain_priority_score
= 0.32*P17 + 0.28*P9 + 0.13*Q6 + 0.12*Q7 + 0.10*RaiseBeat + 0.05*Evidence
```

硬门槛：

- `P17 < 55`：不得进入核心资产库；即使涨得好，也只能是题材/事件交易；
- `P9 < 35`：不得写“当前最值得买”；最多是“好资产但赔率紧 / 等回调”；
- `Q7 < 55`：不得进入右侧买入链；只能低吸或等股性修复；
- `RaiseBeat < 50`：同赛道核心资产横向比较时不得排第一；若连续 miss / guide down，需要说明为什么仍值得跟踪；
- `Evidence < 50`：不得给强结论；标为“需公告/SEC/财报复核”；
- 若标的已涨很多，但 `应得价值 / 当前价格` 仍有显著 gap，且 Q6/Q7 早中期，不因绝对涨幅自动过滤。
- 同赛道三选一时，若 P17/P9 差距不大，优先把持续 raise-and-beat、经营势能越来越强的公司排在前面；这类公司通常股性更顺、右侧持有体验更好。
- 主线确认初期，若某标的是中军/定价锚且 RepresentativeRight 高，即使毛利率不性感，也必须进入横向审计；只有 P9 赔率、证据或 Q7 失败时才能降权。

- `InstitutionalCapacity` 默认不直接进入综合分公式，但会影响分层与动作：高容量龙头优先标记为 `主仓配置资产 / PVE_hold候选`；低容量稀缺卡点默认标记为 `试验仓非对称资产`；流动性弱、只涨题材的标的不得被写成主仓候选。

InstitutionalCapacity 分档建议：

| 档位 | 含义 | 报告动作 |
|:---|:---|:---|
| S | 大资金首选配置入口；市值/成交额/解释成本/板块代表权都强 | 可列 `主仓配置资产`，若 P9/Q6/Q7 通过，进入买入链优先评估 |
| A | 可配置，但需估值、兑现或股性配合 | 核心资产库 / 等回调 / 等验证 |
| B | 逻辑强但容量有限，更适合小仓试验 | `试验仓非对称资产`，不得与主仓龙头混同 |
| C | 流动性弱、题材化或机构难配置 | 温度计 / 验证观察 / 不进主仓 |

## ⚠️ 边界与反模式

**自动建档不做：**

- 不实际下单；
- 不默认跑 P5/P12；
- 不默认对每只 A 类生成长篇初始调研；
- 不把所有 A 类都塞进动态 Watchlist；
- 不把观察壳冒充完整深度调研；
- 不只因为涨停/新高就判定“最值得买”；
- 不只 rank 孤立单票而忽略同一主线的中军/弹性/补涨/价格发现结构；
- 不因低毛利、低净利率、商业模式不性感，就静态跳过市场已选择的平台型中军。

**反模式：**

- 用 10 份浅报告制造“系统很勤奋”的错觉；
- 只看 P17，不看 P9，导致“好资产但太贵”也追；
- 只看 P9，不看 P17，导致“便宜垃圾”误进核心库；
- 只看涨幅，不看应得价值 gap，错过抢筹式价值纠错；
- 只看逻辑，不看 Q7 股性，买到长期消耗心态的烂股性票；
- 只挖漂亮 Choke Point，不审计市场第一选择的龙头组，导致看懂赛道但错过主线收益。
