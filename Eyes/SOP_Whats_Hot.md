# What's Hot：A 股全天候动量发现 SOP（公开版）

> 暗号：`跑一下 What's Hot` / `跑一下热门板块` / `看看什么最热`
> 模块：Eyes（A 股价格事件、板块热度与异动归因）
> 输出：`Eyes/Whats_Hot/YYYY-MM/Whats_Hot_YYYY-MM-DD.md`
> 下游：`Eyes/SOP_A股热门观察.md`

## 1. 目标与边界

What's Hot 不预测下一只涨停股，也不把固定涨幅或“创新高”直接当成买点。它要完成的是：

```text
识别当前市场环境
→ 从经过验证的查询模板中选择合适的扫描组合
→ 发现启动、修复、趋势、新高、事件脉冲与负动量
→ 对价格变化做归因并检查板块广度
→ 把值得继续研究的事实交给下游阅读报告
```

核心分工：Human 定义目标、证据要求和风险边界；Agent 在边界内根据 Market Regime 动态选择模板与剧本。问财负责稳定回答横截面事实，本地逻辑负责跨日比较、集合运算、板块聚类和最终判断。

- 动量是研究任务，不是交易信号。
- 扫描范围由市场驱动；个人偏好只能排序和标注，不能过滤市场。
- 美股对 A 股是重要映射输入；不得使用 A 股收盘后才发生的美股行情解释当日 A 股。
- 本 SOP 不写入持仓、Watchlist、核心资产库或任何交易状态机。

## 2. 输入与依赖

### 必需

- `Eyes/scripts/iwencai_stockpick.py`
- 最近 3-7 份 `Eyes/市场洞察/YYYY-MM/`（若存在）
- 最近 1-3 份 `Eyes/美股热门观察/YYYY-MM/` 或 `Eyes/美股热门追踪/YYYY-MM/`
- 最近 3-5 份 `Eyes/A股热门观察/YYYY-MM/`，用于连续剧与方向状态

### 可选

- `持仓与关注/当前关注方向与投资偏好.md`、用户行业词典或观察池。只能用于排序、定向补扫和持仓关联提示；不读取 Strategy Profile。
- `Eyes/scripts/fetch_market_api.py`、`fetch_finnhub_news.py` 或用户自己的新闻源，用于补充催化归因。
- Web 搜索、公司公告、交易所公告、公司 IR 与主流财经媒体。

依赖缺失时允许降级，但报告必须写明缺失项、影响范围与仍可确认的结论。

### 2.1 基本面事件源识别（必须）

归因前先确定本次 `event_source_mode`。只检查凭据是否存在和数据是否健康，**不得输出 Key 值**：

| 顺序 | 模式 | 使用条件 | 处理 |
|:---:|:---|:---|:---|
| 1 | `market_api` | 存在 `YMOS_MARKET_API_KEY`，且 `fetch_market_api.py` 生成可解析、非空、日期匹配的 Raw | 作为本次事件增量主源 |
| 2 | `local_market_insight` | API 未配置/失败，且本地有时间有效的市场洞察 | 读取报告中的事实、来源和日期，不把旧洞察当今日事件 |
| 3 | `rss_local` | 上述均不可用，但 `fetch_rss.py` 可运行 | Raw 落本任务目录，保留逐源状态 |
| 4 | `primary_public` | 仅为重要候选补足 | 公司公告、交易所、监管/政府原文优先 |
| 5 | `price_only` | 事件源均不可用 | 保留价格与广度事实，所有因果归因写“待确认” |

无 API Key 是正常配置，不是任务失败；API 命令 exit 0 但没有生成有效文件，也必须继续降级。报告“参数与数据完整性”或“降级说明”中记录最终模式、数据截至、覆盖和失败层级。

## 3. Market Regime：先决定找什么

每次运行先判三轴，并在报告中写出依据：

| 轴 | 可选状态 | 主要用途 |
|:---|:---|:---|
| 中期路径 | 趋势扩张 / 高位震荡 / 深度回撤 / 底部修复 / 区间轮动 | 决定主推哪些动量剧本 |
| 当日环境 | 普涨 / 结构分化 / 缩量修复 / 恐慌 / 高波动 | 决定阈值档位与负向扫描强度 |
| 板块状态 | 首次启动 / 修复转强 / 趋势延续 / 新高扩张 / 分歧退潮 | 决定每个方向如何解释 |

参考关系：

- 趋势扩张：重点看趋势延续与新高扩张。
- 底部修复：重点看启动与修复领导，不以创新高作为唯一入口。
- 区间轮动：重点看首次启动与事件脉冲。
- 深度回撤或恐慌：重点看负动量、证伪和修复是否开始。
- 高位震荡：同时检查趋势健康度、拥挤度和板块内部背离。

Regime 是 Agent 的选择依据，不是必须精确命中的机械分类器。证据冲突时保留两种解释，并说明哪条次日数据可以裁决。

## 4. 查询契约：有限自由，不做黑盒自由发挥

Agent 只能：选择模板、填写日期或概念槽位、在给定档位间切换。不得每天临时发明整套问句。

统一字段包：

```text
显示成交额、换手率、量比、所属同花顺行业、所属概念
```

日期使用中文交易日，例如 `2026年8月14日`。

### 4.1 推荐模板

| ID | 用途 | 模板 |
|:---|:---|:---|
| A01 | 涨幅异动 | `{DATE}A股非ST，涨幅大于{UP}%，流通市值大于{MV}亿，{FP}` |
| A02 | 涨停归因 | `{DATE}A股涨停，显示涨停原因、连续涨停天数、几天几板、封成比、所属同花顺行业、所属概念` |
| A03 | 20 日新高 | `{DATE}A股非ST，流通市值大于{MV}亿，股价创20日新高，涨跌幅大于0，{FP}` |
| A04 | 60 日新高 | `{DATE}A股非ST，流通市值大于{MV}亿，股价创60日新高，涨跌幅大于0，{FP}` |
| A05 | 1 年新高 | `{DATE}A股非ST，流通市值大于{MV}亿，股价创1年新高，涨跌幅大于0，{FP}` |
| A06 | 跌幅异动 | `{DATE}A股非ST，跌幅大于{DOWN}%，流通市值大于{MV}亿，{FP}` |
| A07 | 20 日强势 | `{DATE}A股非ST，流通市值大于{MV}亿，近20日涨幅大于20%，涨跌幅大于0，{FP}` |
| A08 | 概念涨幅榜 | `{DATE}同花顺概念指数涨跌幅排名前20，显示指数简称、涨跌幅、涨停家数、成交额` |
| A09 | 概念跌幅榜 | `{DATE}同花顺概念指数涨跌幅排名后20，显示指数简称、涨跌幅、涨停家数、成交额` |
| A10 | 单概念广度 | `{DATE}{概念名}概念上涨家数、下跌家数、涨停家数、涨跌幅、成交额` |
| A11 | 定向概念池 | `{DATE}{概念名}，A股非ST，流通市值大于{MV}亿，涨幅大于3%，{FP}` |
| A12 | 深度回撤上涨 | `{DATE}A股非ST，流通市值大于{MV}亿，当前股价距60日最高价跌幅大于20%，涨幅大于5%，{FP}` |

默认参数：`UP=5`、`DOWN=5`、`MV=50`。允许档位：涨跌幅 3% / 5% / 8%，流通市值不低于 50 亿。新高默认 A04，宽口径用 A03，严苛口径用 A04+A05。阈值发生变化时必须在报告说明原因，不能为了凑数量临时发明新门槛。

### 4.2 数据有效性检查

每个 Raw 文件至少记录：实际 query、交易日期、`code_count`、`returned_count`、`all_results_fetched`、生成时间和状态。

必须同时满足：

1. 翻页直到 `returned_count == code_count`；抓不满时标记不完整。
2. 检查返回字段中存在目标交易日的涨跌幅、新高或回撤证明列；缺失时不能把 `status=OK` 当成条件已生效。
3. 历史日期查询保留 `涨跌幅大于0/小于0` 等日期锚点，避免成交额等字段静默回落到最新交易日。
4. `{概念名}` 优先使用概念榜或返回字段中的同花顺标准名称。

调用示例：

```bash
python3 Eyes/scripts/iwencai_stockpick.py \
  "2026年8月14日A股非ST，涨幅大于5%，流通市值大于50亿，显示成交额、换手率、量比、所属同花顺行业、所属概念" \
  --json-out Eyes/Whats_Hot/Raw_Data/2026-08/a01_20260814.json \
  --csv-out Eyes/Whats_Hot/Raw_Data/2026-08/a01_20260814.csv \
  --desc-out Eyes/Whats_Hot/Raw_Data/2026-08/a01_20260814_description.txt \
  --status-out Eyes/Whats_Hot/Raw_Data/2026-08/a01_20260814_status.txt
```

## 5. 六类动量剧本

| 剧本 | 发现目标 | 主要输入 | 进入研究的最低证据 |
|:---|:---|:---|:---|
| 启动型 | 前期不强、当天首次被资金选择 | A01/A02 排除 A07 + 板块广度 | 量价变化 + 同方向多股同步 + 可核验催化 |
| 修复领导型 | 深度回撤后率先恢复的领导者 | A12 + 近 5-10 日相对强度 | 跑赢指数/行业 + 有催化 + 不是孤立反抽 |
| 趋势延续型 | 当天未必大涨但持续走强 | A07 + 最近 20 日 A04 出现次数 | 多日相对强、回撤浅、板块结构未破坏 |
| 新高扩张型 | 20/60/250 日突破 | A03/A04/A05 | 档位越深越强；同时检查放量、拥挤和回踩 |
| 事件脉冲型 | 单一政策、财报、收购、审批等冲击 | A02/A01 + 事件核验 | 只做归因；T+1 至 T+3 扩散后才可升级为板块启动 |
| 退潮/负动量型 | 崩塌、趋势破坏、利好不涨或内部背离 | A06/A09 + 历史方向清单 | 跌幅与广度事实，或明确负向归因；不涨本身不等于退潮 |

同一标的可以在不同日期属于不同剧本。剧本描述价格行为；方向状态描述它现在处于兑现、Pending、消化、分化还是证伪，两者不要混为一谈。

## 6. 归因与 M/A/Q/S 裁决

对候选分别回答四个问题，不强制加权成一个总分：

| 维度 | 问题 | 强证据示例 |
|:---|:---|:---|
| M · Market | 市场真的在交易它吗 | 板块广度、成交额、相对强度、跨日持续性 |
| A · Attribution | 为什么现在涨跌 | 财报与指引、订单、政策、合同、供需或跨市场映射 |
| Q · Quality | 需求能否进入收入、利润或现金流 | 量价、份额、产能、订单、商业模式与可计算弹性 |
| S · Stage | 处于什么阶段、主要风险是什么 | 启动、修复、延续、拥挤、分化、退潮或待验证 |

裁决原则：

- M 强但 A 弱：只能作为价格线索，不能写成基本面趋势。
- A 强但 M 弱：进入 Pending，等待价格表达。
- M+A 强但 Q 弱：可能是事件脉冲，不升级为持续主线。
- M+A+Q 强且 S 仍早：优先进入研究。
- S 已拥挤或证伪：即使前三项强，也必须把阶段风险写在结论里。

归因来源优先使用公司公告、财报/IR、交易所与监管文件、政府原文和主流财经媒体。没有可靠来源时明确写“归因未确认”，不要用题材常识补齐。

## 7. 执行顺序

1. 确定最近完整收盘的 A 股交易日；休市日不伪造新报告。
2. 识别基本面事件源并记录 `event_source_mode`、日期与降级状态。
3. 读取最近市场洞察、A/美股热门观察和用户可选关注配置。
4. 完成 Market Regime 三轴判断，列出启用与降级剧本。
5. 基座必跑：A01、A02、A03、A04、A06、A08、A09。
6. 根据 Regime 加跑 A05、A07、A10、A11、A12；所有实际 query 落 Raw。
7. 校验行数、日期字段与条件证明列，再做本地去重、集合运算和板块聚类。
8. 对显著方向完成公开事实归因、板块广度和 M/A/Q/S 裁决。
9. 生成报告并完成自检；同日重跑时保留备份或可恢复版本。

## 9. 自检与失败处理

- 报告日期、Raw 日期和交易日期一致。
- 所有强结论都能回到价格事实与可核验来源。
- 没有把“涨幅大”“创新高”或“个人关注”直接等同于值得买入。
- 没有用个人偏好过滤全市场扫描。
- 事件脉冲与持续动量已经分开。
- 不涨没有被自动判为退潮；负向结论具备回撤、广度或归因证据。
- 表格中的代码、公司、涨跌幅和来源可追溯。
- 任何失败池、抓取不完整和搜索失败均已显式记录。

问财不可用时，可以用市场洞察、公开行情与新闻生成 best-effort 版本，但标题下必须标注“条件选股数据缺失”，且不得伪造池数量、板块广度或排名。
