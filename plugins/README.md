# YMOS 插件开发指引（Beta · 早期尝鲜）

> 这是 YMOS **桌面工作站**的一个早期能力：把你自己的面板 / 小工具挂进工作站左侧导航。
> **可选、演进中（Beta）。** 不用桌面客户端也不影响 YMOS——插件本身仍是普通文件夹与脚本，任意 Agent 都能直接调用；客户端只是给它加了一个"点一下就打开"的入口。

## 这是什么

YMOS 桌面工作站的内置服务器会扫描工作区的 `plugins/` 目录，把每个带 `plugin.json` 的文件夹识别成一个**面板**，自动列进左侧「自定义导航」。你可以用它把「一个自建看板」「一个盯盘小工具」「一个外部系统的网页」接进工作站，和 Console、Reader 并排使用。

它解决的是**接入**，不接管你的判断，也不改变「Human 决策、Agent 不自动交易」的边界。

## 目录约定

```text
你的YMOS工作区/
└── plugins/
    ├── README.md            # 就是这份指引
    └── my-panel/            # 一个插件一个文件夹
        └── plugin.json      # 必需：声明清单
```

- **推荐**：所有插件收进 `plugins/`，一个插件一个子文件夹——保持工作区根目录干净、便于 Git 模块化、不污染 Reader 目录树（类比 WordPress `wp-content/plugins/`、Obsidian、VS Code extensions）。
- **兼容**：也识别工作区根目录第一层的 `<插件名>/plugin.json`（框架目录与构建目录除外），但不推荐——会让根目录变乱。

## plugin.json 规范

| 字段 | 必需 | 类型 | 说明 |
|:---|:---:|:---|:---|
| `name` | ✅ | string，≤60 | 显示在导航里的名字；留空则用文件夹名 |
| `entry` | ✅ | string | 面板地址，**必须是 `http://` 或 `https://` 的 URL**（客户端在标签页里打开它） |
| `icon` |  | string（emoji），≤8 | 导航图标，默认 🧩 |
| `hasBackend` |  | boolean | 这个插件是否需要一个后端服务；默认 `false`（纯前端） |
| `backendPort` |  | integer 1–65535 | 后端端口（声明用，方便你自己核对，见下方「两类插件」） |
| `cmd` |  | string，≤300 | 启动后端的命令（**仅声明，客户端当前不会替你自动执行**） |
| `notes` |  | string，≤500 | 一句话描述，给自己/别人看 |

校验：**没有 `name` 或 `entry` 不是合法 http(s) URL 的清单会被忽略**，不会出现在导航里。

### 例子

纯前端面板（entry 指向一个网页）：

```json
{
  "name": "我的宏观看板",
  "icon": "🌐",
  "entry": "http://127.0.0.1:8899/",
  "notes": "本机跑的一个静态看板，随手看几个宏观指标"
}
```

带后端的面板：

```json
{
  "name": "情绪监测器",
  "icon": "📟",
  "entry": "http://127.0.0.1:7020/",
  "hasBackend": true,
  "backendPort": 7020,
  "cmd": "python3 server.py",
  "notes": "自建的舆情打分服务，先自行启动，再在工作站里打开"
}
```

## 两类插件

- **纯前端**：`entry` 指向一个能打开的网页 URL。如果它只是一个静态页面，最简单的做法是让它随一个本机小服务器一起跑（哪怕 `python3 -m http.server 8899`），`entry` 填那个 `http://127.0.0.1:8899/`。
- **带后端**：设 `hasBackend: true` 并写上 `backendPort` / `cmd`。**当前版本客户端只做「识别 + 列出」，不会替你启动后端**——你自己把服务跑起来，客户端负责在导航里打开 `entry`。`cmd` 只是给你和协作者看的声明，不是"授权自动运行"。

## 客户端怎么发现和加载

1. 客户端内置服务器扫描 `plugins/*/plugin.json`（+ 根目录兼容），通过 `GET /api/plugins` 暴露识别结果；
2. 工作站把识别到的插件自动列进左侧「自定义导航」（**只读**：由清单决定，不在导航里手改）；
3. 安装 / 卸载在「**系统管理 → 插件管理**」：选一个含 `plugin.json` 的文件夹，客户端把它归置进 `plugins/<名>/`；卸载即从 `plugins/` 移除（有严格的路径与越界校验）。

## 边界与安全

- **不要把密钥、账户、Token 写进 `plugin.json`**——它是明文、会被识别与展示。密钥走工作区 `.env` 或客户端「数据源配置」页。
- 插件是**文件夹资产**，不是 YMOS 的内核。它不参与策略判断、不改门禁、不写真相源；把它当成一个"外挂的入口"，而不是第二套逻辑层。
- 客户端**不自动执行** `cmd`。带后端的插件由你自己启动，风险自负。
- 这是 **Beta（早期尝鲜）**，`plugin.json` 字段与加载方式可能随版本演进。
