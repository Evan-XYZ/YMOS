# 优化建议归档

内核进化的**证据层**。这里存的不是结论，是从真实执行里提取出来的、可以被反复检验的原始判断记录。

```text
Brain/内核审计/优化建议/
└── YYYY-MM/
    ├── YYYY-MM-DD_{TICKER}_平仓复盘.md      ← 单笔平仓后逐笔提取
    └── YYYY-MM-DD_周期审计.md               ← 跨笔聚合，找重复模式
```

## 为什么单独存一层

一笔交易的复盘结论，单看没有意义——**任何一笔的输赢都可能是运气**。

有意义的是同一类缺口重复出现。所以这里的文件不直接触发内核修改，它们是给周期审计读的原料：只有当同一个结构缺口在多笔里反复出现，才值得写成判断层变更提案。

| 层 | 文件 | 作用 |
|:---|:---|:---|
| 证据 | `优化建议/YYYY-MM/*_平仓复盘.md` | 单笔：计划与实际差在哪 |
| 聚合 | `优化建议/YYYY-MM/*_周期审计.md` | 跨笔：哪类缺口在重复 |
| 提案 | `内核审计/` 下的判断层变更提案 | 改什么、反证是什么、怎么回滚 |

## 写入规则

- **只追加，不修改。** 已归档的复盘不得因为后来的行情变化而回头改写——那正是这套记录要防的事。
- 由 Agent 起草，**Human 确认后才落盘**。
- 复盘结论里不写"下次应该……"这类决心，只写可观察的事实和可检验的假设。
- 单笔复盘**不修改** Profile、P 系列、SOP 或 Console 规则。任何内核修改都要走变更提案。
