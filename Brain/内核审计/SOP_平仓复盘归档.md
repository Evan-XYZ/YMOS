# SOP：平仓复盘归档

> 暗号：`复盘一下这笔` / `复盘一下 [ticker]` / `归档一下上个月的平仓`

## 定位

每笔平仓后，把这一笔的**计划与实际**提取成一份可检验的记录，落进 `优化建议/YYYY-MM/`。

这是整个系统里**证据密度最高**的一环：单笔决策文件从建档到平仓，完整保留了你当初怎么想、后来做了什么、最后发生了什么。别的语料靠回忆，这一份靠事件流。

它不改任何内核文件，也不给"下次要注意"这种决心。它只负责把证据固定下来，让周期审计有东西可读。

## 与 P11 的分工

| | P11 交易复盘 | 本 SOP |
|:---|:---|:---|
| 是什么 | 策略内核层的**判断工具** | 内核审计的**归档流程** |
| 回答 | 这笔交易怎么看 | 这套系统在这笔里有没有按设计工作 |
| 产出 | 分析（读完就完） | 落盘证据（喂给周期审计） |

先跑 P11 得到分析，再用本 SOP 归档；也可以直接跑本 SOP，它会在需要判断时调用 P11。

## 触发

- 单笔文件状态变为 `已平仓` 并移入 `Brain/买入卖出决策/已平仓/`。
- 用户主动说 `复盘一下 [ticker]`。
- 周期审计发现某笔尚未归档。

## Step 0：先读 Strategy Profile

**这一步不能跳。** 同样一笔交易，在不同策略族里意味着完全不同的东西：

- 趋势派持有 3 天就止损 → 正常执行。
- 价值派持有 3 天就止损 → 严重的裁判错配，说明入场逻辑和认错逻辑不属于同一套。

所以必须读取 `Brain/策略配置/当前策略_Profile.md`，确认：

| 读什么 | 用来判断 |
|:---|:---|
| `strategyFamilies` | 这笔属于哪一族，该用哪套裁判标准 |
| `decision.invalidation` | 这笔当初写的失效信号，符不符合该族的认错方式 |
| `risk.thesisHorizonMonths` | 实际持有天数和论点周期是否匹配 |
| `execution.requiredGates` | 该走的门禁有没有走 |
| `conflictPolicy` | 混合策略时，这笔该听哪个裁判的 |

**Profile 缺失或仍为 `draft`** → 只做 Step 2 的机械对账，不做判断力评价，并提示用户先完成内核配置。没有 Profile 就评价判断力，等于拿作者的标准去量用户。

`持仓与关注/当前关注方向与投资偏好.md` 可以补充当时研究背景，但不能替代 Profile，也不能提供入场、失效、风险或门禁裁判。

## Step 1：读取事件流

打开已平仓单笔文件，按顺序取：

| 来源 | 提取什么 |
|:---|:---|
| `ymos-trade-open` | 原始论点、失效信号、催化剂、退出逻辑 |
| `prepare` / `revise` | 计划金额、止损位、论点周期、资金期限、出局权 |
| `fill` | 实际成交价、股数、实际投入 |
| `add` / `tp` / `sl` | 每次动作的时点、价格、比例、当时理由 |
| `adjust` | **旧规则 → 新规则**，以及调整理由 |
| `close` | 平仓价、实现盈亏、结果验证 |

补充证据（有才读，缺失不阻塞）：

- 当前 Strategy Profile（Step 0 已读）。
- `Brain/交易计划/` 对应日期的盘前计划与盘中实际。
- `Brain/决策审计/` 里这笔的放行与拦截记录。
- `BrainStorm/` 里与这笔直接相关的 Insight。

## Step 2：机械提取（先不解释，只对账）

这一步全部是**可以从事件流直接算出来的事实**，不需要判断，也不允许加解释：

| 检查项 | 怎么算 | 触发条件 |
|:---|:---|:---|
| `amountOverPlan` | `fill.实际投入` vs `prepare.计划金额` | 超出即记 |
| `stopLossWidened` | 遍历 `adjust`，比较新旧止损**相对成本价**的距离 | **距离变大 = 放宽，红旗** |
| `addedWhileLosing` | `add` 事件时点的价格 < 当时成本价 | **摊低成本，红旗** |
| `invalidationTriggered` | 失效信号是否在持仓期内出现过 | 需人工确认，Agent 只提问 |
| `exitedOnInvalidation` | 触发后到实际退出之间隔了多久 | 隔越久问题越大 |
| `intradayImprovised` | 该日交易计划台有无对应的盘前条目 | 无 = 盘中临时决定 |
| `gateBypassed` | 决策审计里有拦截但仍然成交 | 绕过门禁，红旗 |

### 移动止损不算放宽

判定基准是**止损相对成本价的距离**，不是止损的绝对价格：

- **向上移动止损**（成本 100、止损从 92 抬到 105）→ 距离缩小，属于**止盈范畴**，不记红旗。
- **放宽止损**（成本 100、止损从 92 降到 85）→ 距离变大，记红旗。

换句话说：移动止损是在**收紧**风险敞口，本来就不该被这条规则拦。真正要抓的是**把认错线往后挪**。

### 放宽之后赚钱了，也是红旗

`stopLossWidened` 与最终盈亏**完全解耦**。放宽止损后这笔最终盈利，不仅照记，而且更值得单独标注：

> 亏钱的违规会自己疼，赚钱的违规会被记成"幸好我当时扛住了"——然后变成下一次放宽的理由。

所以复盘时对这类要额外问一句：**如果当时价格没有回来，这笔会亏多少？** 用那个数字、而不是实际结果，来判断这次放宽值不值。

> **三个红旗的意义**：放宽止损、亏损加仓、绕过门禁，是"人系统性背叛自己规则"最典型的三种形态。
> 它们和盈亏无关——**这笔赚钱了也照记**。

## Step 3：判断力与执行力分开问

按模板第 2、3 节填写。两组问题必须分开，因为它们指向不同的修法：

- **判断力有问题** → 可能要改内核（P 系列、Profile 字段）。
- **执行力有问题** → 优先加操盘层门禁，**不要动策略**。

把这两者混在一起，最常见的后果是：因为没执行到位而亏钱，却回头把策略改松了。

## Step 4：归类，只选一类

A 策略按设计运行但结果不利 / B 执行偏离 / C 规则模糊或冲突 / D 驱动数据问题。

**A 类不改规则。** 一个正期望的策略也会有连续亏损，把正常波动当成缺口去修，是这类系统最典型的死法。

## Step 5：只登记，不提案

在 `优化建议/` 历史文件里搜同类缺口，记录它是第几次出现。

**然后就停在这里。** 单笔复盘**不生成提案、不触发任何内核修改**，哪怕这个缺口看起来很明显。

提案由周期审计统一产出——它需要横跨足够多的样本才能分清"重复的结构缺口"和"连续的运气不好"。一笔交易提供不了这个区分。

> 单笔的输赢是运气，一类缺口的重复才是信号。

## Step 6：写盘

路径：

```text
Brain/内核审计/优化建议/YYYY-MM/YYYY-MM-DD_{TICKER}_平仓复盘.md
```

- `YYYY-MM-DD` 用**平仓日**，不是复盘日。
- 用 `_模板_平仓复盘.md`。
- 展示全文给 Human，确认后才写入。
- 已归档文件**只追加不修改**——后来行情怎么走，都不允许回头改写当初的复盘。

## 不做什么

- 不修改 Profile、P 系列、SOP 或 Console 规则。
- 不根据单笔结果调整任何阈值。
- 不生成判断层变更提案——那是周期审计的职责。
- 不写"下次一定"这类无法检验的决心。
- 不因为这笔赚钱就跳过违规记录。
- 不替 Human 判断失效信号是否触发过——不确定就标记为待确认。
