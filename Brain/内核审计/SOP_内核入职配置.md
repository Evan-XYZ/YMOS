# SOP：内核入职配置

> 暗号：`配置一下我的内核` / `帮我建立策略 Profile`

## 定位

把用户已经拥有的策略表达整理成 YMOS 配置。Agent 负责发现模糊和矛盾，用户负责选择策略、数值与取舍。

## Step 0：识别入职模式

先问用户选择哪条路径，不要求用户理解 Profile Schema：

- **快速建立**：第一次使用、没有完整旧策略，或只想先形成最小可运行内核。
- **从已有资料整理**：已有 V3 偏好、P/SOP、投资日志、复盘或 BrainStorm，希望保留证据并找出矛盾。

如果用户只是想看市场、做事实研究，不强迫进入本 SOP；返回投研层继续运行即可。

系统不配送默认激活的通用策略。模板只预置以下结构不变量：`status: draft`、Human 最终确认、决策与执行分离、空字段不猜。市场、策略族、裁判、仓位、损失预算、期限和模块都必须来自用户。

## Step 1A：快速建立最小内核

Agent 一次只问一组，允许用户回答“不确定”。不要把 JSON Schema 一次性甩给用户。

1. **范围**：主要做什么市场和工具？能力圈是什么？明确不做什么？
2. **入场**：一笔机会至少要看见哪些证据？哪些证据不能单独触发动作？
3. **认错**：什么可观察信号说明原论点失效？出现后默认暂停、减仓、退出还是重新审计？
4. **风险与期限**：仓位按什么计算？单笔上限、损失预算、论点周期和资金可用期限是什么？
5. **加减仓**：什么情况下允许加仓、禁止加仓、减仓或必须退出？
6. **节奏与门禁**：多久监控和复核一次？哪些步骤必须由 Human 确认？盘中禁止改什么？

根据回答推荐“需要哪些能力模块”，但只使用人类可读名称解释作用；在保存前再展示对应 P/SOP 清单，由用户决定启用、停用或替换。Agent 可以推荐结构不变量模块，不能把作者扩展或个人参数当默认答案。

若任一动作级必填项仍不确定：

- 保持 `status: draft` 与 `meta.approvedByHuman: false`；
- 用“待确认问题”列出缺口；
- 明确告诉用户：投研层可继续，动作级请求会返回 `kernel_not_ready`，这不是运行故障；
- 不为了通过校验而制造数字或判断。

## Step 1B：从已有资料运行结构诊断

读取 `Brain/ymos-diagnosis/SKILL.md`，使用“结构体检”模式，至少检查：

- 策略能否复述。
- 入场、认错、仓位和期限是否一致。
- 规则是否可证伪。
- 决策与执行是否分离。
- 是否存在可审计真相源。

不得依据用户自称的流派直接下结论；同时核对用户描述的实际行为。

## Step 2：选择结构参照

可读取 `Brain/ymos-diagnosis/references/strategy_family_map.md`，把策略族当成访谈坐标，不当成标准答案。允许混合，但混合部分必须写清各自的裁判和冲突处理。

## Step 3：生成四个草案

完整模式先将 Human 确认的诊断保存到 `Brain/内核审计/诊断记录/YYYY-MM/YYYY-MM-DD_结构诊断.md`；快速模式把本轮访谈摘要记录为 Profile 的来源。然后生成四份草案：

1. Strategy Profile：基于模板，目标路径 `Brain/策略配置/当前策略_Profile.md`。
2. 驱动清单：目标路径 `Brain/策略配置/驱动清单.md`，记录市场、数据源、Skills、新鲜度与失败降级。
3. 模块清单：目标路径 `Brain/策略配置/模块清单.md`，记录启用、停用、替换的 SOP/P/Agent/Console 能力。
4. 执行投影：目标路径 `Console/rules.json`，只投影 Profile 已确认的判断问题与红线。

所有阈值保持空白，直到用户亲自提供。

## Step 4：一致性复核

逐项展示冲突，不替用户选择。例如：

```text
你把基本面证伪写成主要裁判，但同时要求任何价格回撤都立即退出。
这两条在第一次正常波动时会冲突。请选择主裁判，或写明二者的优先级。
```

## Step 5：分两次 Human 确认

### 5.1 保存草案

先展示六项摘要：策略一句话、入场、认错、风险期限、加减仓、模块与门禁，并列出所有空白和矛盾。只有用户确认“这准确表达了我目前的想法”后，才能把运行副本保存到 `Brain/策略配置/当前策略_Profile.md`，状态仍为 `draft`。

### 5.2 激活内核

只有机器校验通过，并且用户再次明确确认“启用这份策略内核”后，才能：

- 将 Profile 状态从 `draft` 改为 `active`。
- 同时将 `meta.approvedByHuman` 设为 `true` 并记录诊断来源路径。
- 更新 `持仓与关注/当前关注方向与投资偏好.md` 的兼容视图。
- 生成 `Console/rules.json` 所需的操盘层投影。
- 记录哪些模块被停用以及原因。

没有第一次确认时只在对话中输出草案，不修改运行文件；没有第二次确认时保留 `draft`，不投影动作门禁。

## Agent 遇到动作级请求时的标准响应

当 Profile 缺失或仍为 `draft`，不要只返回裸错误：

```text
当前不是程序故障，而是策略内核尚未完成确认（kernel_not_ready）。
市场洞察、投资雷达和事实调研仍可继续；但系统还不知道你用什么证据入场、何时认错、怎样限制风险，所以不会替你生成个性化动作结论。
如果你愿意，我现在可以用快速模式逐题帮你建立最小策略内核。
```

用户同意后从 Step 1A 开始；用户拒绝则回到投研层，不反复打断。

## Day 0 边界

Day 0 可以完成一致性、可证伪化、节奏和模块配置，但不能凭空定位“历史上真正缺失的拦截点”。拦截点必须等系统积累真实计划与执行偏差后，由周期审计提出。
