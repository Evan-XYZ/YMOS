# 内核审计

策略内核层的**进化机制**。它负责四件事：

1. Day 0 把用户的策略表达整理成可运行的 Strategy Profile。
2. 持续接收旧日志与 BrainStorm，保存策略来路、反复困惑和规则冲突。
3. 每笔平仓后，把「计划 vs 实际」提取成可检验的证据并归档。
4. 按提案类型使用认知语料或跨笔结果证据，提出可证伪、可回滚的内核变更建议。

它不判断策略能不能赚钱，不替用户设置参数，也不自动修改内核。

## 完整反馈闭环

```text
旧日志 / BrainStorm 帮助梳理信念、困惑与矛盾
  ↓
策略内核层做出判断
  → 操盘层留下证据（论点、门禁、成交、事件流）
  → 平仓后逐笔提取（SOP_平仓复盘归档）
  → 优化建议归档（按月/按日）
  → 跨笔聚合找重复（SOP_内核周期审计）
  → 判断层变更提案（含反证与回滚）
  → Human 审批
  → 策略内核层更新
  → 下一次判断时生效
```

**关键在于它是闭合的**：BrainStorm 与旧日志可以先帮助用户把策略说清楚；操盘层证据再验证判断与执行。任何材料都不能自动修改策略内核，必须经过提案、Human 审批和后续复核。

## 四个进化来源

| 来源 | 最适合提供什么 | 使用边界 |
|:---|:---|:---|
| **BrainStorm / 旧投资日志** | 策略来路、反复困惑、信念冲突和候选规则 | 是梳理内核的重要上下文，不自动生效 |
| 交易计划 vs 盘中实际 | 日级执行偏差 | 用来区分判断问题与执行问题 |
| 决策审计 | 门禁放行、拦截与绕过 | 验证门禁，不单独证明策略有效 |
| **已平仓单笔** | 论点、计划、实际动作与最终结果的完整对账 | 最完整的单笔验证证据，但单笔仍不改内核 |

用户自述 + 结构诊断是第五个来源。它不只用于 Day 0：之后仍可借助 BrainStorm 继续澄清规则和发现矛盾；但凡声称“这条规则在真实操作中有效”，就必须让计划、执行与结果证据说话。人的自述是重要上下文，不是效果证明。

## 两类变更提案

| 类型 | 主要证据 | 门槛 |
|:---|:---|:---|
| **规则澄清型** | 结构诊断、旧日志、BrainStorm 中可定位的歧义、冲突或真相源不一致 | 可直接起草，但只能进入 `trial`；必须保留改前表述并设置反证、复核和回滚 |
| **结果验证型** | 平仓归档、计划偏差、决策审计的跨笔重复模式 | 走周期审计；建议至少 10 笔已归档平仓证据，并点名证据 |

前者回答“规则是否说得清、彼此一致”，后者回答“规则放进真实操作后是否有效”。不能用 BrainStorm 代替结果验证，也不能用样本门槛阻止修复一条已经明确自相矛盾的规则。

## 入口

| 入口 | 什么时候 | 输入 | 输出 |
|:---|:---|:---|:---|
| `SOP_内核入职配置.md` | Day 0 | 用户自述 + 旧日志 / BrainStorm + 结构诊断 | Strategy Profile 草案、模块与投研清单 |
| `../../BrainStorm/SOP_头脑风暴.md` | 日常思考、旧日志整理或发现规则冲突时 | Raw 思考 + 近期 Insight + Profile | 结构化 Insight、待验证问题或规则澄清型提案草案 |
| `SOP_平仓复盘归档.md` | 每次平仓后 | 单笔已平仓文件的事件流 | `优化建议/YYYY-MM/*_平仓复盘.md` |
| `SOP_内核周期审计.md` | 积累足够样本后 | 优化建议归档 + 计划/审计/Profile | `优化建议/YYYY-MM/*_周期审计.md` + 变更提案 |
| `_模板_判断层变更提案.md` | 确认缺口重复出现后 | 单个结构缺口 | 可证伪、可审批、可回滚的修改记录 |

## 规范落盘路径

- 已确认结构诊断：`诊断记录/YYYY-MM/YYYY-MM-DD_结构诊断.md`
- 周期审计：`优化建议/YYYY-MM/YYYY-MM-DD_周期审计.md`
- 单项变更提案：`优化建议/YYYY-MM/YYYY-MM-DD_{主题}_判断层变更提案.md`

诊断记录与优化建议都是个人运行数据，公开仓只保留说明与模板。

## 三条硬规矩

1. **单笔结果不改内核。** 结果验证型提案遵守跨笔门槛；明确的规则歧义或冲突可以起草澄清型提案，但只能先试运行，不能宣称已经验证。
2. **没有反证条件的修改不予受理。** 每个提案必须写明"如果这次改错了，我会在什么情况下看到"。
3. **放宽类修改额外举证。** 任何降低门槛的修改，必须说明触发它的证据在原规则制定时是否已知——已知的不算新证据，算找借口。

这三条防的是同一件事：**系统朝着「越来越会同意你」的方向进化。**
