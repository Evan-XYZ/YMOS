> **作者内核扩展｜`disabled_by_default: true`** 完整保留为真实研究链样本。它不会进入新用户的最小闭环；只有 Human 点名且用户已完成 P17/Profile 映射时才启用。

> 暗号：`跑一下 [ticker/名称] 的 P9/P17` / `用 P9 和 P17 看一下 [ticker]` / `专项调研 [ticker]` / `基本面兑现链 [ticker]`
> 迁移暗号：`把潜在观察 [ticker/名称] 移入真实观察` / `移入真实观察 [ticker/名称]`
> 模块：Brain/（大脑 — Human 指定标的的基本面兑现链补审）
> 最后更新：2026-05-12 CST（v1.3：统一五段式动作建议：核心资产 → 应得价值 → 当前势能 → 股性/资金认可 → 执行动作建议）

## 一句话定位

这个 SOP 处理一种高频场景：**不是系统从热门池里发现标的，而是 Human 在聊天、看盘、读新闻时已经点名一个标的，要求 Agent 直接跑 P9 + P17，判断它是否值得后续跟踪。**

它是“动量发现与基本面兑现链”的手动入口，但默认只进入“潜在观察”，不直接进入正式观察状态机：

```text
Human 指定 / 潜在观察清单
  → 补齐最小上下文 / 证据链
  → P9 对标估值与内在价值锚
  → P17 v4 核心资产判定（资产等级 ≠ 当前买点 + Q7 股性/可持有性审计）
  → 输出五段式动作建议（核心资产 / 应得价值 / 当前势能 / 股性资金认可 / 下一步链路建议）
  → 写入 手动调研/美股潜在观察 或 手动调研/A股潜在观察
  → 追加 Brain/策略分析/YYYY-MM/策略分析日志_YYYY-MM-DD.md
  → 给出是否“建议移入真实观察”的结论
  → 仅在 Human 明确确认后，才迁移到美股观察 / A股观察并更新状态机
```

核心原则：**Human 指定调研 ≠ 自动进入正式 Watchlist。先放潜在观察，做完 P9/P17 再由 Human 决定是否移入真实观察。**

### 默认不做

- 不默认跑 P5 / P12。
- 不默认给买入建议。
- 不默认更新正式观察状态机，也不默认写入 `A股观察/A股Watchlist状态机.md` 或 `美股观察/美股Watchlist状态机.md`。
- 不默认写入 `核心资产库/核心资产状态机.md`。
- 不默认写入 `动态Watchlist/`。
- 不把用户提供的个人短线交易流水写入状态机；除非用户明确要求记录。

## 输入来源

### 1. Human 直接点名

最低输入：

```yaml
target: ticker 或 中文名 / 英文名
market: 可选；未知时由 Agent 解析
user_context: 可选；用户口述的关注原因、交易背景、新闻、对标逻辑
requested_scope: 默认 P9 + P17；若用户要求，可补 P1/P2/P4 或 P5/P12
```

### 2. 潜在观察清单

清单路径：

```text
YMOS/持仓与关注/手动调研/感兴趣的潜在观察标的.md
```

清单里每个候选应尽量包含：

```yaml
- id: A-20260511-001
  market: A股 / 美股
  ticker: 300751.SZ
  name: 迈为股份
  source: Human手动记录 / 新闻 / 聊天 / 行情
  thesis_hint: HJT/光伏设备潜在修复；疑似A类候选
  priority: P0 / P1 / P2
  expected_class: A? / B? / unknown
  status: todo / running / done / skip
```

Agent 消费规则：

- 只消费 `status: todo` 且优先级最高的若干条。
- 每次建议批量：A股 <= 4，美股 <= 6。
- 跑完后把该条状态改为 `done`，并写入报告路径与结论摘要。
- 如果信息不足，改为 `needs_info`，不要假装完成。

## 执行步骤

### Step 0：确认任务类型

| 类型 | 处理方式 |
|:---|:---|
| Human 点名，问“怎么看 / P9P17 / 专项调研” | 跑本 SOP，默认落潜在观察 |
| Human 明确说“我想买 / 加仓 / 卖” | 转 `SOP_策略分析.md`，必要时先用本 SOP 补 P9/P17 |
| 批量观察池自动建档 | 转 `SOP_Watchlist自动建档.md` |
| Human 说“移入真实观察” | 执行本 SOP 的“潜在观察 → 真实观察迁移”段 |

### Step 1：解析标的与市场

1. 解析名称、ticker、市场、交易所后缀。
2. A 股统一用带交易所后缀：`688449.SH` / `300751.SZ` / `830000.BJ`。
3. 美股统一大写 ticker（如 `AMD`、`NVDA`）。
4. 判断是否已经存在于：
   - `持仓与关注/手动调研/A股潜在观察/`
   - `持仓与关注/手动调研/美股潜在观察/`
   - `持仓与关注/持仓/`
   - `持仓与关注/动态Watchlist/`
   - `持仓与关注/A股观察/单标的/`
   - `持仓与关注/美股观察/单标的/`
   - `Brain/策略分析/` 与既有报告
5. 如果已有潜在观察目录，优先追加更新；如果只有宽表/主题材料出现，则新建潜在观察单标的目录。

检索建议：

- 先用 `search_files` 搜 ticker、中文名、英文名。
- 若中文路径漏检，再用 Python `Path.rglob()` 在 YMOS 根目录下搜目录与文件名。
- 结论中写清：“找到既有独立档案 / 仅在宽表出现 / 未找到历史材料”。

### Step 2：读取必要前置

必须读取：

```text
YMOS/持仓与关注/当前关注方向与投资偏好.md
YMOS/Brain/references/p9-valuation.md
YMOS/Brain/references/p17-core-asset.md
```

按需读取：

```text

YMOS/Brain/references/p4-radar.md
既有个股基础知识库 / 历史报告 / 买入卖出备忘录
你自己的产业链索引或主题子链材料（可选）
最新市场洞察 / 美股热门追踪 / What’s Hot 报告
```

只有执行“移入真实观察”时才必须读取：

```text
A股 → YMOS/持仓与关注/A股观察/A股Watchlist状态机.md
美股 → YMOS/持仓与关注/美股观察/美股Watchlist状态机.md
若 Human 要求核心库同步 → YMOS/持仓与关注/核心资产库/核心资产状态机.md
```

### Step 3：补最小证据链

目标不是写百科，而是给 P9/P17 足够证据。

#### A 股数据层

优先跑问财四层数据：

```bash
cd "<你的 YMOS 根目录>"
python3 Eyes/scripts/iwencai_finance_query.py "股票名 最新一期 营业收入 净利润 毛利率 净利率 ROE 资产负债率 经营现金流 最新价 涨跌幅 市值" -l 3
python3 Eyes/scripts/iwencai_finance_query.py "股票名 最近年报 营业收入 归母净利润 扣非净利润 毛利率 净利率 经营现金流 合同负债 货币资金 研发费用" -l 3
python3 Eyes/scripts/iwencai_finance_query.py "股票名 近20日涨跌幅 近60日涨跌幅 近120日涨跌幅 年初至今涨跌幅 60日新高 250日新高 成交额 换手率 市值" -l 3
python3 Eyes/scripts/iwencai_finance_query.py "股票名 20日均线 60日均线 120日均线 250日均线 近20日振幅 近60日最大回撤 近60日成交额均值" -l 3
python3 Eyes/scripts/iwencai_announcement_search.py "股票名 最新一季报 年报 业绩预告 公告" -l 8
python3 Eyes/scripts/iwencai_report_search.py "股票名" -l 5
python3 Eyes/scripts/iwencai_news_search.py "股票名 核心业务 最新新闻" -l 8 --days 30
```

P9/P17 专项调研不要只看“最新一期”：

- P9 估值必须同时拿最近年报口径，否则 PE/PS 和终局市值会被单季度扰动带偏。
- P17 Q6 必须尽量拿价格动量 / 新高 / 成交额口径；如果问财动量查询返回 0 rows，报告里要说明降级使用新闻层或外部行情线索。
- P17 Q7 必须尽量拿相对强度、均线结构、回撤修复、量价健康和事件反馈证据；如果数据源不足，允许用可得价格序列/行情源降级计算，但必须标注缺口。
- 若 `fetch_price_router.py` 返回 `no_data`，可用问财财务层最新价/市值作本轮策略锚，但关键交易前仍需行情源复核。

优先级：

```text
财务结构化数据 + 公告事实层 > 研报叙事层 > 新闻事件层 > 热门初筛
```

若 `fetch_price_router.py` 对 A 股返回 no_data，允许使用问财财务层返回的 `最新价 / 涨跌幅 / 市值` 作为本轮策略锚，但必须注明“交易前仍需行情源复核”。

#### 美股数据层

建议最小数据：

1. 当前价格、市值、涨跌幅、52周区间：优先复用 `Eyes/scripts/fetch_price_router.py`。
2. 最新 10-K / 10-Q / 8-K / IR deck / earnings release。
3. 收入、毛利、经营利润/净利、经营现金流、现金、债务、RPO/backlog（如适用）。
4. 对标公司市值、收入、利润、PS/PE/EV/Sales。
5. 近 30 天重大新闻 / 财报事件 / 价格事件。

注意：跨币种公司不要直接引用可能币种混用的 `priceToSalesTrailing12Months`，必须手动重算。

### Step 5：执行 P9 估值 / 内在价值锚

P9 必须回答：

1. 当前估值快照：市值、PS、PE、EV/Sales、利润/现金流口径。
2. 对标参照系：它应该对标谁？为什么？
3. 份额捕获：它能捕获哪条利润池？收入/利润上限由什么决定？
4. 终局市值区间：Base / Bull / Bear。
5. 当前价格是否已经 price in 未来 3-5 年增长。
6. 安全边际：舒服区 / 可研究区 / 不追价区。
7. 潜在收益分级：A1短势35-50% / A2龙头70-100% / A3右侧强势150-300% / A4长线3-5倍 / A5长线5-10倍 / 暂不分级。

所有估值倍数、比例、反推市值、目标价区间必须用工具计算，不心算。

### Step 6：执行 P17 v4 核心资产判定

P17 必须输出两层结论：

```text
资产等级：A_core / A_high_odds / B_tracking / P2_conditional / Block
当前机会标签：accumulation_early / wait_pullback / conditional / block
股性/可持有性：score 0-100 + 类型 + 是否支持核心跟踪
潜在收益分级：A1 / A2 / A3 / A4 / A5 / 暂不分级 + 理由
```

七问必须完整：

1. Q1：它是不是核心资产？
2. Q2：内在价值 / 对标参照系是否成立？
3. Q3：能捕获多少份额？
4. Q4：稀缺性溢价有多高？
5. Q5：站在产业终局和牛市视角，未来 3-5 年空间是否还够？
6. Q6：结合当前市值、价格事件、传播阶段，它处于右侧早期 / 中期 / 末期，还是只适合等待回调？
7. Q7：股性 / 可持有性审计——相对强度、上涨捕获、下跌抵抗、回撤修复、趋势流畅、量价健康、事件反馈是否支持进入核心资产池或重点 Watchlist？

Q7 评分建议：相对强度 25 / 上涨捕获 15 / 下跌抵抗 15 / 回撤修复 15 / 趋势流畅 15 / 量价健康 10 / 事件反馈 5。输出股性类型：`核心资产型好股性 / 趋势可交易型股性 / 逻辑强但股性弱 / 脉冲交易型股性 / 恶劣股性`。

裁决纪律：

- A 类资产不等于当前可以买。
- Human 有潜在倾向，但 Agent 必须独立评判。
- 默认不确定时，放 `B_tracking`，不要硬升 A。
- 如果资产稀缺、对标清楚、终局空间足、价格仍未完全兑现，可升 `A_high_odds`。
- 如果是强题材但事实层弱，放 `P2_conditional` 或 `B_tracking`。
- 如果利润兑现明显落后但赔率有吸引力，写成“高赔率观察”，不要写成“舒服长拿核心仓”。
- 如果 Q1-Q5 强但 Q7 <55，或股性类型为“逻辑强但股性弱 / 脉冲交易型股性 / 恶劣股性”，不得直接写成 `A_core` 舒服长拿；只能写 `A_high_odds` / `B_tracking` / `P2_conditional`，并注明“只低吸不追 / 等股性修复 / 需要更高赔率补偿”。


### Step 6.5：输出五段式动作建议

P9/P17 专项调研的结尾必须额外输出五段式，方便 Human 直接决定是否迁移、建档或进入买入链：

```text
1. 核心资产：A_core / A_high_odds / B_tracking / P2 / Block + 一句话理由
2. 应得价值：P9 应得估值区间 + 当前 gap + 赔率是否足够
2.5 潜在收益分级：A1/A2/A3/A4/A5/暂不分级 + 兑现周期 + 成立条件
3. 当前势能：Q6 阶段 + 催化/财报/价格事件 + 是否早中期
4. 股性/资金认可：Q7 分数 + 类型 + 市场是否愿意表达

```

## 潜在观察 → 真实观察迁移

### 触发暗号

```text
把潜在观察 [ticker/名称] 移入真实观察
移入真实观察 [ticker/名称]
把 [ticker/名称] 加入 A股观察/美股观察
```

### 执行动作

1. 读取潜在观察目录下的：
   - `个股基础知识库.md`
   - 最新 `YYYY-MM-DD_{TICKER}_P9_P17_{名称}调研分析.md`
   - Raw JSON
2. 判断市场：A股 / 美股。
3. 复制或迁移到正式观察目录：
   - A股：`持仓与关注/A股观察/单标的/{主线}_{名称}_{代码.交易所}/`
   - 美股：`持仓与关注/美股观察/单标的/{主线}_{名称}_{TICKER}/`
4. 更新对应观察状态机：
   - A股：`持仓与关注/A股观察/A股Watchlist状态机.md`
   - 美股：`持仓与关注/美股观察/美股Watchlist状态机.md`
5. 如果 P17 明确是 `A_core` / `A_high_odds` 且 Human 要求进入核心资产库，再同步：
   - `持仓与关注/核心资产库/核心资产状态机.md`
6. 在潜在观察原目录保留链接或 README 说明：
   - “已于 YYYY-MM-DD 移入真实观察，正式路径：...”
7. 在策略分析日志追加“迁移记录”。

## 潜在观察清单维护建议

文件：

```text
YMOS/持仓与关注/手动调研/感兴趣的潜在观察标的.md
```

建议结构：

1. `## Inbox`：用户随手记录，Agent 可先解析。
2. `## 待调研队列`：结构化 YAML / 表格，Agent 消费 `status=todo`。
3. `## 已完成`：跑完后归档结论和报告路径。
4. `## 暂缓 / 跳过`：信息不足或不值得跟踪。

### 后台消费建议

后续可以单独建一个 cron：

```text
暗号：消费潜在观察标的
建议频率：每日 13:30 或 21:30，北京时间
单次处理：优先 P0/P1，A股 <= 4，美股 <= 6
输出：潜在观察目录 + 策略分析日志；不更新正式观察状态机
```

不建议一开始全自动高频跑太猛。先手动/半自动跑 3-5 次，看命中质量，再上 cron。

## 质量门槛

### 必须有

- 当前价格 / 市值 / 估值锚。
- P9 对标参照系。
- P17 七问判定卡（含 Q7 股性 / 可持有性）。
- 资产等级和当前机会标签分开。
- 股性评分、股性类型、是否支持核心资产池 / Watchlist 写清楚。
- 升级条件、降级条件、回调/观察区。
- 单标的报告 + 个股基础知识库 + Raw JSON。
- 策略分析日志追加记录。
- 明确“是否建议移入真实观察”。

### 不能有

- 不读数据直接凭印象写“核心资产”。
- 把热门上涨直接翻译成“可以买”。
- A 类资产和 A 类买点混在一起。
- 把用户个人短线交易流水写进状态机。
- 默认更新 A股/美股观察状态机。
- 默认写入核心资产库。
- 只写报告，不写策略分析日志。
