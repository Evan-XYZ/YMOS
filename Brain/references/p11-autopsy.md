# P11: 投资交易复盘 (Autopsy)
> **策略内核层 · 进化语料入口｜`invariant`** 「每笔平仓后区分策略错、执行错、运气」是内核能进化的前提，不可省略。三个评分维度是结构约束，但**权重**由你的行为弱点决定——执行经常变形的人应该给纪律执行更高权重。

## 路径上下文（YMOS）
- 根目录：`YMOS/`
- 主证据：`Brain/买入卖出决策/已平仓/` 的单笔事件流
- 必须读取：`Brain/策略配置/当前策略_Profile.md`、对应 `Brain/交易计划/` 与 `Brain/决策审计/`
- 可选读取：个股知识库、相关投研、BrainStorm 原始复盘与历史资料
- 写回：`Brain/内核审计/优化建议/YYYY-MM/YYYY-MM-DD_{TICKER}_平仓复盘.md`
- 禁止写回：旧 `买入卖出备忘录.md`、持仓/Watchlist 状态机、当前 Profile 或交易事件

## 适用场景

对已平仓事件流做计划—实际复盘，区分策略按设计运行、执行偏离、规则冲突与数据问题。单笔只登记观察，不直接修改内核。

## 提示词模板

```
# Role
你是一名 **冷酷的交易审计员**。
请对我刚刚结束的一笔交易 **[{{ticker}}]** 进行"尸检"。目标不是安慰我，而是找出系统漏洞。

# Context (User Input)
1. **Ticker:** {{ticker}}
2. **Closed Trade Event File:** {{closed_trade_file}}
3. **Strategy Profile:** {{profile}}
4. **Plan / Decision Audit:** {{plan_and_audit}}

# Audit Protocol

## 1. 知行合一检查
* 从 `open / prepare / fill / tp / sl / adjust / close` 机械提取计划与实际。
* 买入理由和退出理由是否使用同一套裁判；若 Profile 定义了冲突优先级，按该优先级检查。

## 2. 运气 vs 实力
* 结果由论点兑现、环境、执行还是未识别因素贡献？证据不足就写未知。
* 盈亏不能单独证明规则有效或无效。

## 3. SOP 优化
* 只选择 A 策略按设计运行 / B 执行偏离 / C 规则冲突 / D 数据问题中的一类。
* 单笔只写观察登记；提案交给周期审计并遵守样本门槛。

# Output Format
* **计划 vs 实际:** [事件证据表]
* **原因归类:** [A/B/C/D + 证据]
* **三红旗:** [风险规则被放宽 / 违反 Profile 加仓规则 / 门禁绕过]
* **观察登记:** [本次暴露的缺口与历史复现次数]
* **Human 确认:** [未确认前不得生成变更提案]
```

## 输入参数

| 参数 | 说明 | 必填 |
|-----|------|-----|
| `ticker` | 股票代码 | 是 |
| `closed_trade_file` | 已平仓的 V4 单笔事件文件 | 是 |
| `profile` | 该笔交易适用的 Strategy Profile | 是 |
| `plan_and_audit` | 对应交易计划与门禁审计 | 否；缺失时标 `data_incomplete` |

## 复盘评分标准

权重由你在 Profile 里定义。三个维度本身是结构约束（缺一个就无法区分"策略错"和"执行错"），但它们的相对重要性取决于你的行为弱点：执行经常变形的人应该给"纪律执行"更高权重。

| 评分维度 | 权重 | 说明 |
|---------|-----|-----|
| 知行合一 | 由 Profile 定义 | 买卖理由是否匹配 |
| 纪律执行 | 由 Profile 定义 | 是否按计划止损/止盈 |
| 逻辑验证 | 由 Profile 定义 | 投资逻辑是否得到验证 |

## 常见缺口（只能按 Profile 判断）

| 漏洞类型 | 表现 | 改进方向 |
|---------|-----|---------|
| 调研不深 | 买入后才发现关键风险 | 强化 P1 调研流程 |
| 证据外入场 | 实际理由不在 Profile 入场证据中 | 检查入场门禁或执行偏离 |
| 退出裁判漂移 | 实际退出理由与 Profile 冲突策略不一致 | 先区分规则冲突还是执行偏离 |
| 风险扩大 | `adjust` 使风险边界扩大但没有新证据 | 强化操盘层解释与二次确认 |
| 加仓错配 | `add` 不满足 Profile 的加仓证据和限制 | 强化加仓门禁；不得预设所有下跌加仓都错误 |
| 门禁绕过 | 审计记录 `passed=false` 后仍出现未授权事件 | 优先修执行门禁，不据此改宽策略 |

## V4 写回合同

使用 `Brain/内核审计/优化建议/_模板_平仓复盘.md` 保存单笔复盘。复盘文件引用源事件，不改写事件；`humanConfirmed=false` 时只是候选观察。当前样本不足时，周期审计只能生成观察记录，不得用单笔盈亏修改 Profile、P、SOP 或 Console 规则。
