# 买入卖出决策（Trade Decision Journal）

> 单标的、单笔交易的决策真相源。由 `Console/买卖决策台.html` 通过本地服务写入，历史事件 append-only。

## 为什么必须落 Markdown

买卖决策台不是一个只在浏览器里勾选的表单。本目录保留每笔交易从买入论点、建仓准备、实际成交、持仓调整到平仓验证的完整证据链，使人和 Agent 都能继续复盘、审计和优化。

- `_模板_买卖决策_状态机.md`：公开的空数据结构；首次启动服务后生成正式的 `买卖决策_状态机.md`。
- `买卖决策_状态机.md`：账户参数、资金流水、最近行情与 Agent 持仓体检快照；属于用户运行数据，默认不进入 Git。
- `标的_Ticker_日期.md`：一笔交易的完整生命周期；论点和事件只追加，不覆盖历史。
- `已平仓/`：完成结果验证后自动归档。

单笔文件是持仓事实源；账户状态机里的 `portfolioSnapshot` 是最近一次行情刷新生成的派生视图，不是第二套持仓账本。

## Agent 快速读取顺序

1. 先读 `买卖决策_状态机.md` 的 `portfolioSnapshot.accounts`、`positions`、`health` 与 `agentRouting`。
2. 只有某笔仓位出现止损、期限、敞口或论点告警时，再打开对应的单笔 Markdown。
3. 按 `持仓与关注/SOP_持仓日常体检.md` 输出体检结论，并按建议调用 P2 / P6 / P7 / P12。

## 数据链路

正式使用必须从本地服务打开：

```bash
cd Console
python3 server.py
```

然后访问 <http://localhost:5273>。直接双击 HTML 只是页面预览，不会写入本目录；公开版只把本地服务写入的 Markdown 视为真相源。

## 生命周期与不可变边界

`计划中 → 持仓中 → 已平仓`

- 成交前可以复核计划，但每次修订都追加成新事件。
- 成交后不能改写当时的论点与建仓档案；调整止损必须留下新事件和理由。
- 平仓后写入结果验证，并移入 `已平仓/`。
- 只有 YAML front matter 中的当前状态、股数和成本等事实可以更新；事件流永远只增不改。

这套通用数据契约不会把作者扩展或默认参数内置进决策台，但完整保留 YMOS 的 Markdown-first、可审计和可演化能力。
