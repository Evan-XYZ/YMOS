# 策略分析 SOP

> 暗号：`我想买 [ticker]` / `加仓 [ticker]` / `我想卖 [ticker]` / `持有怎么看 [ticker]` / `检查一下持仓` / `做个仓位再平衡`

## 定位

策略分析连接投研层、策略内核层与操盘层：读取最新研究事实和买卖决策状态，使用当前 Strategy Profile 审计论点与风险，再把待确认事项交给 Human。它不自动交易，也不把单次结果直接写成新规则。

## 真相源

按顺序读取：

1. `Brain/策略配置/当前策略_Profile.md`（唯一生效 Profile）；
2. `Brain/买入卖出决策/买卖决策_状态机.md` 的账户与组合快照；
3. 目标单笔决策 Markdown（股数、成本、论点、退出规则的事实源）；
4. `持仓_状态机.md` 与 `Watchlist_状态机.md` 的身份和分类；
5. 最新有效投研数据、市场洞察和投资雷达；
6. 历史研究与 BrainStorm 只作为证据，不自动覆盖当前 Profile。

Profile 缺失或仍为未批准草稿时，允许做只读体检与事实整理；动作级结论返回 `kernel_not_ready`。

## 模块路由守卫

读取 Profile 的 `modules` 后再解释下方链路：

1. `disabled` 中的模块不得读取或执行。
2. `replacements` 中存在替代项时，只运行替代模块。
3. 标记为 `profile` / `optional` 的模块未列入 `enabled` 时，返回 `module_not_configured`，不得使用作者默认语义。
4. 模块需要的裁判、阈值、模型参数或风险字段为空时返回 `data_incomplete`；不得从 P 文件示例或模型常识补齐。
5. `invariant` 模块只默认启用其通用检查流程；具体问题、红线和尺度仍从 Profile 注入。

## 数据口径

- 持仓市值 = 最新已保存价格 × 持仓数量。
- 账户净值 = 可用现金 + 持仓市值（跨币种前必须有明确汇率与时间）。
- 未实现盈亏单独展示，不重复计入可用现金。
- 快照必须显示 `asOf`；过期数据可用于恢复展示，不能用于声称实时触发。
- 快照和单笔文件冲突时以单笔事件文件为事实源，并要求重建快照。

## 日常监控：L0 → L2

### L0 组合扫描

只读 `portfolioSnapshot.accounts / positions / health / agentRouting`，输出账户敞口、盈亏、行情覆盖和告警。无告警时返回 `no_change`，不展开所有标的。

### L1 告警聚焦

仅打开告警关联的单笔文件，复现原论点、失效信号和退出规则：

| 告警 | 分析路由 |
|---|---|
| 价格或逻辑退出条件可能触发 | P2 → P3（有事件时）→ P6 → P12 |
| 仓位、期限、流动性或集中度冲突 | P7 → 对候选运行 P6 → P12 |
| 数据过期或来源异常 | 返回投研层刷新任务，不给动作结论 |

### L2 组合再平衡

只在 Human 明确要求，或出现组合性异常时运行完整 P7。目标分类、比例和阈值全部来自 Profile；未配置时只报告当前结构与风险，不代填目标。

## 动作路由

| 意图 | 必需链路 | 操盘入口 |
|---|---|---|
| 首次买入 | 按模块守卫解析 P2 → 按需 P9 → P5 → 最终裁判 | 买卖决策台“买入逻辑” |
| 加仓 | 复现原论点 → 按模块守卫解析 P2/P3/P9/P5/P7/最终裁判 | Human 确认后由 Console 追加 `add` |
| 持有 | 复现原论点与退出规则 → 按模块守卫解析 P2/P3/P6/最终裁判 | 只写策略报告；保持不变无需事件 |
| 减仓/退出 | 复现原规则 → 按模块守卫解析 P3/P6/P7/最终裁判 | Human 确认后由 Console 追加 `tp/sl/close` |
| 调整退出规则 | 旧规则 → 新证据 → 新规则 → P6 → 最终裁判 | Human 确认后由 Console 追加 `adjust`，保留旧值 |
| 衍生品 | Profile 明确允许后运行已启用的 P10 与最终裁判 | Human 在外部账户执行并通过 Console 留痕 |

买入逻辑通过后即可建立决策文件；建仓准备阶段必须再次复现论点和失效信号，允许成交前修订。通过审计不等于成交，只有实际成交后才把计划变成持仓事实。

## 状态写回

分析阶段只写 `Brain/策略分析/` 下的策略报告或待确认清单。P 模块不得直接写旧 `买入卖出备忘录.md`、状态机或 V4 单笔事件。只有 Human 明确确认且真实动作发生后，Console / Portfolio State 才能：

1. 追加单笔事件，不覆盖旧论点；
2. 更新当前股数、成本和状态；
3. 记录账户资金变动的日期、旧值、新值和原因；
4. 重建 `portfolioSnapshot` 并保存；
5. 保存后重读文件，自动刷新页面与全局状态。

已平仓目录默认不参加日常敞口计算，只在 P11、行为审计或 Human 点名时读取。

## 内核演化

若多个独立案例持续暴露同一冲突，运行 `ymos-diagnosis` 区分策略结果、执行偏差、策略内核冲突与投研数据质量。需要改规则时只起草内核变更提案，经 Human 批准、设定证伪条件与回滚方案后更新 Profile。
