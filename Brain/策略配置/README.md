# 策略配置（Strategy Profile）

Strategy Profile 是 YMOS 策略内核层的唯一策略接口。它描述“用户怎样判断”，不保存账户、持仓或行情。

> **Profile 不是量化策略**——它不预测收益、不生成信号、不做回测；它是**你既有判断的结构化表达**：把你脑中的入场证据、失效信号、风险预算、退出裁判写下来，让 AI 帮你在关键时刻不走样地执行。策略只能从你自己的实盘经验里长出来，Profile 是它的对外接口。

## 文件

| 文件 | 作用 |
|:---|:---|
| `strategy-profile.schema.json` | 机器可校验的语义接口 |
| `_模板_策略_Profile.md` | Human 与 Agent 共用的空白模板 |
| `当前策略_Profile.md` | **唯一生效的运行 Profile**；由入职流程生成，属于用户运行数据，不进入 Git |
| `驱动清单.md` | 当前 Profile 所需数据、Skills、失败降级与新鲜度规则；运行数据 |
| `模块清单.md` | Profile `modules` 的展开说明，记录各 P/SOP/Agent/Console 能力的依赖与替换理由；运行数据，不是第二真相源 |
| `examples/` | 禁用的参考实例，不是默认策略 |

`examples/author-profile/` 保存作者愿意公开的真实内核扩展示例；其中 `module-manifest.example.json` 是默认关闭的启用清单。它用于说明 P17、P18、专项调研、热门追踪和资产库治理怎样接入 Profile，不会自动加入新用户的运行链或定时任务。

正式使用时，由入职配置器根据模板生成 `Brain/策略配置/当前策略_Profile.md`。它是唯一的**策略判断真相源**；`模块清单.md` 是展开说明，冲突时以 Profile 为准。

`持仓与关注/当前关注方向与投资偏好.md` 属于投研层高频状态，不是 Profile 的投影，也不存在覆盖关系：它回答“最近研究什么”，Profile 回答“怎样判断、何时认错、如何约束风险”。Profile 的创建、激活和修改都不得自动改写关注文件。

## 第一次使用：不配送“通用激活策略”

不存在对所有人都安全的仓位、止损、期限和退出裁判。一个预先激活的 Demo Profile 虽然能少报几个状态，却会在用户不知情时替他做出最重要的策略选择。因此 V4 配送的是**可运行的草稿骨架**，而不是公共投资策略。

首次使用有两条正常路径：

| 目的 | Profile 要求 | 结果 |
|:---|:---|:---|
| 先看市场、做事实调研 | 不需要 active Profile | 市场洞察、投资雷达、Reader 和基础事实研究照常运行 |
| 需要买卖、持有、加仓、退出或再平衡判断 | 需要个人 active Profile | 说“配置一下我的内核”，由 Agent 逐题建立并经 Human 激活 |

快速入职只问六组人类问题：范围、入场证据、失效信号、风险期限、加减仓、节奏与门禁。用户可以回答“不确定”；缺口会留在草稿中，不会被模型猜测。完整流程见 `Brain/内核审计/SOP_内核入职配置.md`。

Profile 完全不存在时，含义只是“尚未启用个性化策略内核”，不是 YMOS 未初始化。投研层的数据源、市场范围、当前关注和报告模式由 Eyes 层、轻量关注状态或运行配置管理，与 Strategy Profile 分离。

允许预置的只有结构不变量：`draft` 状态、Human 最终确认、决策与执行分离，以及“空字段不猜”。作者示例、模型常识和前端样板都不能成为运行默认值。

## 三种成熟度路径

Strategy Profile 是内核入口，不是价值上限。随着用户对自己策略的理解加深，V4 允许你沿三条合法路径逐步深化，不必永远停留在 Profile 层。三条路径共享同一组不变量（论点可复述、失效信号可检查、决策与执行分离、Human 门禁、事实不可事后覆盖、内核变化必须 Human 审批并可回滚），差异只在于**策略特化的表达方式**。

| Tier | 表达方式 | 适合谁 | 出口机制 |
|:---|:---|:---|:---|
| **Tier 1：入门** | 只填 Profile，不动 P 模块 | 新用户；跨市场轻度使用者 | 按 `_模板_策略_Profile.md` 完成六组人类问题 |
| **Tier 2：多策略并行** | Profile 保留通用元数据，策略特化条款拆到 `策略手册/{family}.md` | 同时跑 2+ 种策略、entry / exit / cadence 差异显著的用户 | Profile 里声明 `strategyFamilies`，配套 `Brain/策略配置/策略手册/{family}.md` |
| **Tier 3：硬编码专精** | 通过 `modules.replacements` 挂私版 P 模块或 SOP | 长期单策略深度用户；策略 know-how 已超出声明式字段能表达的范围 | 在 `Brain/私有/` 写私版模块并加入 `.gitignore`，Profile 里声明 `"replacements": { "P5": "私有/P5_我的版本.md" }` |

### Tier 2 vs Tier 3 的分辨

- 策略之间的差异是**参数**（阈值 / 期限 / 仓位口径不同，判据结构相同）→ 走 Tier 2 的策略手册。
- 单策略内部的差异是**过程**（if/else、优先级、市场周期切换等无法用 requiredEvidence 数组表达）→ 走 Tier 3 的私版模块。

### Tier 3 的合规边界

- 私版模块必须遵守公版 P 模块的输入 / 输出契约：相同的错误码语义（`kernel_not_ready` / `module_not_configured` / `data_incomplete`）、相同的状态写回规则、相同的失败降级路径。
- 私版模块放在 `Brain/私有/` 或其他被 `.gitignore` 排除的路径，不进入公开仓库。
- 私版模块不得绕过 Human 门禁、状态机或本 README 的不变量清单；它只替换"怎么判断"，不替换"谁最终决定"。
- 公版 P 模块升级时，只需检查私版是否仍满足接口契约；Profile 本身通常不用改。

参考实例见 `examples/author-profile/module-manifest.example.json` —— 作者的模块清单展示了 Tier 3 的一种可能形态，默认 `disabled_by_default`，不会加入新用户的运行链。

## 状态与路由守卫

- `draft` Profile 只服务后续策略梳理，不作为市场洞察、投资雷达或热门观察的输入；不得产生买卖、持有、加仓、退出或再平衡结论。
- 动作级任务只有在 `status: active` 且 `meta.approvedByHuman: true` 时才可继续；否则返回 `kernel_not_ready`。这表示“需要完成配置”，不是脚本崩溃；Agent 应解释边界并询问是否进入快速入职。
- 调用任何 P 模块前先检查 `modules`：`disabled` 不读取；`replacements` 改读替代模块；`profile` / `optional` 模块未启用时返回 `module_not_configured`。
- 模块需要的参数在 Profile 中为空时返回 `data_incomplete`，不得从 P 文件、作者示例或模型常识补默认值。

## 不变量与用户变量

YMOS 固定的不变量：

- 论点必须可复述。
- 失效信号必须可检查。
- 仓位风险和资金期限必须可计算。
- 决策与执行必须分离。
- 事实和事件不得被事后覆盖。
- 内核变化必须由 Human 审批并可回滚。

用户自己决定：

- 做什么市场和策略。
- 使用什么证据和裁判。
- 所有阈值、期限与仓位参数。
- 哪些模块启用、停用或替换。

`Console/rules.json` 是 Strategy Profile 在买卖决策台上的执行投影，不是独立真相源。
