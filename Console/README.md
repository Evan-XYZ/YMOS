# YMOS Console — Reader 与决策台

> 一个本地入口，做三件事：**翻报告、定计划、过门禁。**

YMOS 的 Eyes / Brain / 持仓与关注 解决的是「信息怎么进来、怎么分析、状态记在哪」。
Console 把 Reader 与两个决策台合在同一个进程、同一个端口里：Reader 解决「报告产出太多，怎么顺手翻」；
决策台解决最后一厘米——**从「我知道该怎么做」到「我真的按它做了」之间那道坎。**

所有产出都是纯 Markdown，写回**你自己的 Obsidian vault**。没有数据库、没有云端、没有账号。

---

## 三个页面

| | Reader | 交易计划台 | 新高买卖决策台 |
|---|---|---|---|
| **用在什么时候** | 日常阅读 | 收盘后 | 盘中出手前 |
| **解决什么** | 报告聚合与检索 | 决策与执行解耦 | 冲动与流程解耦 |
| **怎么用** | 选分类 → 搜索 → 阅读 | 定调 → 审持仓 → 审观察 → 列明日动作 | 选模式 → 逐条勾 → 全绿才能扣扳机 |
| **产出** | 只读，不产出 | `<plan_dir>/YYYY-MM/YYYY-MM-DD日交易计划.md` | `<audit_dir>/YYYY-MM/YYYY-MM-DD决策记录.md` |

### Reader

把散在不同目录、不同月份里的市场洞察、投资雷达、策略分析和决策记录聚在一个页面。
它只读，不修改 vault；正文宽度、对齐和字号都可调。

Reader 不承担定时任务管理。任务启停与运行状态留在 Agents 层，Reader 只负责阅读真正的产出。

### 交易计划台
把明天要做的事，在**收盘后的冷静期**全部想完写完。第二天开盘，你只是一个照着计划执行的机器人——
计划内的动作是绿的，计划外的动作会被标红拦一下。

标的是**常驻名单**，跨天保留；每天只更新趋势、计划、动作。次日盘中还能回填「实际执行了什么」，
和昨晚的计划做偏差对比。

### 新高买卖决策台
五个模式：收盘定调 / 开新仓 / 低多加仓 / 止盈 / 止损。每个模式下是若干道**门**，每道门若干条要确认的事。
有些条目是**红线**。全部勾满才允许「扣扳机」；漏了就弹出来告诉你还差哪几条。

**每一次扣扳机、每一次被拦下来，都会留痕**到你 vault 的决策审计目录里。
不是为了好看——是为了三个月后回头看的时候，你能查到自己当时到底确认了什么、跳过了什么。

## 跑起来

### 最快：先看看长什么样

直接用浏览器打开 `index.html` 可以预览两个决策台。这种模式下数据只存在浏览器本地（localStorage），
不写你的 vault，但导出选项仍可用。Reader 需要本地服务读取目录。

### 正式用：接上你自己的 Obsidian

```bash
cd Console
cp config.example.json config.json     # 然后编辑它
python3 server.py
```

浏览器打开 <http://localhost:5273>。

`config.json` 里改这几项：

| 字段 | 说明 |
|---|---|
| `vault_root` | 你的 vault 里 YMOS 所在的绝对路径。**留空 = 用本仓库根目录**，开箱即可跑 |
| `plan_dir` | 交易计划归档目录，相对 `vault_root`，默认 `Brain/交易计划` |
| `audit_dir` | 决策留痕归档目录，相对 `vault_root`，默认 `Brain/决策审计` |
| `reader_roots` | Reader 允许读取的根目录；相对路径以 `vault_root` 为基准，也支持绝对路径 |
| `reader_pages` | Reader 的分区、分类、目录与扫描方式 |
| `port` | 默认 5273，只绑 `127.0.0.1`，不对外暴露 |

> 需要 Python 3.9+。本地后端**零第三方依赖**，不用装任何 pip 包。
> Reader 默认通过 CDN 加载 `marked` 与 `DOMPurify`；断网时仍能打开，但 Markdown 会降级为原文显示。

## 换成你自己的规则（重要）

决策台里内置的门禁条目与仓位口径（「曲线顺用正常仓」「震荡时减半」「回撤中暂停开新仓」……）
**是一份通用样例，不是标准答案**。精确手数、金额、回撤阈值和熔断周期必须由用户自己定义。
每个人的能力圈、持仓周期、风险偏好和行为弱点不同，规则就不该一样。

```bash
cp rules.example.json rules.json       # 然后改成你自己的
```

改完刷新页面即生效。`rules.json` 里：

- `sizeCap` — 三种资金曲线状态下的仓位口径。需要时再精确到自己的手数、成数或金额。
- `modes` — 五个模式的门禁定义。`rule: "all"` = 这道门每条都要成立；`rule: "any"` = 命中任一条即可；
  `redline: true` = 这条是红线。

删掉某个字段就会退回内置默认，不用整份重写。

> 这正是 YMOS 的核心主张：**框架是共用的，策略是你自己的。**
> 系统不该替你决定什么时候该买——它只该保证，你按自己定的规矩走完了流程。

## 导出

交易计划台右下角四个按钮：

- **⬇️ .md** — 下载 Markdown，可直接拖进任意 vault
- **📋 复制** — Markdown 进剪贴板
- **{ } JSON** — 结构化数据，喂给你自己的 Agent 或其他工具
- **🖨️** — 打印 / 存 PDF

## 快捷键（交易计划台）

| 键 | 作用 |
|---|---|
| `1` – `5` | 切换 tab |
| `⌘S` / `Ctrl+S` | 保存当前 tab |
| `⌘←` / `⌘→` | 前后切换日期 |
| `Esc` | 关闭弹窗（决策台） |

三个页面的正文右边缘都可以拖动调宽，首次打开会给提示，默认停在可用宽度约 75% 的位置；
双击边缘恢复默认宽度。

> 页面本身也是样板。除了改 JSON，你也可以让自己的 Agent / 编程工具按偏好继续修改布局、字段和工作流。

## 数据落在哪

```
<vault_root>/
├── <plan_dir>/                        默认 Brain/交易计划
│   ├── _当前草稿_自动备份.md            实时草稿镜像（清缓存也能恢复）
│   └── YYYY-MM/
│       └── YYYY-MM-DD日交易计划.md      人读的正文 + 机器读的 JSON 围栏
└── <audit_dir>/                       默认 Brain/决策审计
    └── YYYY-MM/
        └── YYYY-MM-DD决策记录.md        每次扣扳机 / 被拦截的留痕
```

计划文件里嵌了一个 ```json 围栏（`ymos-plan-data`），既能被人读，也能被页面和 Agent 解析回填。
这是 YMOS 一贯的做法：**同一份文件，人和机器都能用。**

## 安全边界

- 服务只绑 `127.0.0.1`，不监听外网。
- Reader 只能读取 `reader_pages` 明确列出的目录。
- 写入路径**由服务端从日期生成**，前端不能传路径——防止越权写入你 vault 的任意位置。
- 只写 `plan_dir` 和 `audit_dir` 两个目录，不碰别的。
- `config.json` 和 `rules.json` 已在 `.gitignore` 里，不会被误提交。
